# 电力系统设计（电压 / 电流 / 功率 / 线损）

> 状态：**四级首轮实现**。本文是电力系统的**唯一权威文档**；实现以原生 V/A/W/J
> 模型为准，普通 Core 设备不暴露 FE。
>
> **已定（批注）**：
> - 电压阶梯采用方案 1——真正的代差是 **380 V / 10 kV / 110 kV / 500 kV**；
>   **220 V 单相与 380 V 三相不是两个等级**，而是 **LV 级内部的接线方式**（§4）。
>   工业设备**绝大多数就是 380 V**，高压（10 kV/110 kV）用于**传输与发电侧**（§4.2）。
> - **等级与电压一起显示**（如 `MV · 10 kV`），代码用 LV/MV/HV/EHV（§4.4）。
> - 导线有两个**正交属性**：**绝缘等级**（只影响触电安全与载流量降额，不会击穿爆炸）与
>   **载流量**（超过后热量累积，最终断线或爆炸）（§6）。导线分**硬质铜排**（沉浸工程式）与**柔性导线**（现实式，
>   端子 + 连线）两类（§6.2）。**端子 = 端子座 + 端子**：端子座提供规则网格（**LV 4×4=16 格 /
>   MV 2×2=4 格 / HV、EHV 1×1=1 格**），玩家**自由选格**放单个端子；网格只开在一个面上、
>   端子座是**六向表面件**（贴墙 / 平铺地面 / 倒挂天花板）；镐挖散开掉落、安装工具 Shift+右键完整取下（§6.3）。**多导体**：
>   一条线多根；**相序不建模**（§6.4、§6.5）。
> - **多芯线缆**（一根走多芯，专用节点**只直通不分路**，§6.6）；**线槽**（一格最多 32 根、
>   连接材质、开口朝上；**进槽线缆长度 = 端子→入口 + 入口→出口 + 出口→端子，三段各自取整后相加**，§6.7）；
>   **线缆可上色**区分线路（16 色，纯标识、不影响电气，§6.8）。
> - **线缆是「连接」不是「方块」**：没有方块形态、不占格子、没有碰撞箱，只是两个端子之间的
>   一条数据；每维度的 `ElectricalNetworkSavedData` 是唯一权威存储，端子方块实体只保留已加载
>   区域的渲染/求解缓存。**一个端子可接多根线**（§6.9.2）。
> - 触电按线路本 tick 的实际带电电压与绝缘等级判定：裸线在 LV 轻伤、MV 起致命；
>   一类绝缘在 MV 轻伤、HV 起致命；二类绝缘在 HV 起致命。服务端使用与渲染相同的
>   悬垂折线和线径检测玩家身体接触，轻伤/致命伤害均可配置（§6.11）。
>   软线**悬链线下坠仅视觉**，电气长度 = 直线距离四舍五入到整数格（§6.9）。
> - **端子用 OBJ 模型 + 贴图**（每级一份材质），端子座为**六向**表面件（§6.3.3）。
> - 设备层引入**保护**（过压 / 过载 / 缺项），**机器本身不带保护，保护全部外置**；
>   **无保护时**高电压进低压设备**只炸端口**，威力随等级差按 `2 × 3^(Δ−1)` 个 TNT 放大，
>   **默认不破坏地形**（§8）。**欠压 = 无反应+提示；带电缺项持续 40 tick = 炸（2 TNT）**（§4.3、§8）。
>   爆炸参数当前仍使用代码固定值；触电开关与轻伤/致命伤害已接入 `Config`（§8.6）。
> - **单相 + 平衡三相模型**：单相按 `P=U_phase·I`，三相按
>   `P=√3·U_line·I`；三相四线在平衡负载下中性线电流为 0。功率因数固定为 1，
>   不求相角、无功、相序、频率或并网同步，但 `√3`、每相电流和三相总线损进入求解（§3.1、§6.12）。
>   换算锚点固定为 `1 FE = 1 J`。
>
> **本轮实现范围（已定）**：打通 **LV / MV / HV / EHV 四级闭环**，包含燃料发电机、
> 创造调试电源、相邻级变压器、储能、破碎机、断路器/保险丝与专用 FE 转换器。
> 多芯线、线槽、硬质铜排仍留待后续。
>
> **故障确认规则（已定）**：储能内部使用 J，面向玩家按数值自动显示 kWh/MWh/GWh；当所需导体没有接全、但至少一根
> 导体已由闭合的上游电源带电时，才算带电缺相并进入破坏判定。所有可能爆炸的电气故障都
> 必须连续存在至少 **40 tick** 才能进入爆炸路径；过流还需满足更长的热累积时间。未通电的
> 半成品接线、瞬时拓扑抖动和区块加载不会立即破坏设备。
>
> 本文同时记录**目标设计与当前实现边界**；§12 是实现状态的权威清单，明确标为后续的项目不属于当前版本。

## 0. 为什么要做这件事（与 FE 的区别）

现在绝大多数模组用电网（Forge Energy / FE，旧称 RF）作为统一电力。FE 的设计目标
是"让所有模组的机器能互相供电"，因此它被刻意简化到只剩**一个标量：能量（t）**。

用你的话说：**"FE 与其说是电，不如说是流体。"** 一根导线接上去就工作，没有电压、
没有电流、没有极性问题、没有线损——因为它本来就不是在模拟电，而是在模拟"能量管道"。

本模组要做的是一套**真正的电学模型**：

| 概念 | FE | 本设计 |
|---|---|---|
| 能量 | ✅ 一个标量（FE/t） | ✅ 功率对时间的积分（J） |
| 电压 | ❌ 无 | ✅ 网络属性，决定"能不能接" |
| 电流 | ❌ 无 | ✅ 由负载决定，决定"导线够不够粗" |
| 功率 | 与能量混淆 | ✅ 单相 `P=U_phase·I`；平衡三相 `P=√3·U_line·I` |
| 线损 | ❌ 无 | ✅ `I²R`，与电流平方成正比 |
| 导体根数 | 一根通吃 | ✅ 多导体：每根导线独立，端子可作放射状分线（§6.4） |
| 端子/节点 | 无 | ✅ 可放多根、可旋转、可分线（§6.3） |
| 变压器 | ❌ 无 | ✅ 升压/降压，改变网络的电压 |
| 过压 | ❌ 无 | ✅ 持续确认后炸端口（§8.3） |
| 过流 / 缺项 | ❌ 无 | ✅ 过热炸线、缺相爆炸（§6.10、§8.2） |
| 触电 | ❌ 无 | ✅ 裸露高压线碰到秒杀（§6.11） |
| 保护 | ❌ 无 | ✅ 断路器/保险丝/继电器（§9.3） |

**核心玩法收益**：输电距离第一次变成了**要解决的问题**。低压近距离够用，但远距离
必须升压——这正是现实电网存在高压的原因，也是可以教给玩家的真实工程直觉。

> 现实依据：电力远距离传输使用高压，唯一目的就是**降低欧姆损耗**（同功率下电压越高、
> 电流越小、`I²R` 损耗越小）。1888 年特斯拉/多利沃-多布罗沃尔斯基的三相交流系统之所以
> 击败爱迪生的直流系统，就是因为**变压器让升压成为可能**。这条历史主线就是本系统的玩法主线。

## 1. 前置调研：现实中"有哪些电"

### 1.1 按电压等级分类（IEC 61140）

| 类别 | 交流（RMS） | 直流 | 主要风险 |
|---|---|---|---|
| 特低电压 ELV | < 50 V | < 120 V | 起火 |
| 低压 LV | ≤ 1000 V | ≤ 1500 V | 触电 |
| 高压 HV | > 1000 V | > 1500 V | 电弧 |

注：ELV 是 LV 的**子类**（IEC 61140 把 <50V 归入"低电压"大类的子带）。"高压"
在工程上进一步细分为 HV / EHV / UHV（美国 ANSI C84.1）：

| 类别 | ANSI C84.1（60 Hz 系统） |
|---|---|
| HV 高压 | 115 – 230 kV |
| EHV 超高压 | 345 – 765 kV |
| UHV 特高压 | ≥ 1100 kV |

### 1.2 中国电网标称电压阶梯（GB）

| 区段 | 常用标称电压 |
|---|---|
| 低压 LV | 220 V（相电压）/ 380 V（线电压） |
| 中压 MV | 3 kV、6 kV、10 kV、35 kV |
| 高压 HV | 66 kV、110 kV、220 kV |
| 超高压 EHV | 330 kV、500 kV、750 kV |
| 特高压 UHV | 1000 kV（交流）、±800 kV / ±1100 kV（直流） |

**现实电网中的关键事实：220 V 与 380 V 的关系就是 √3（≈1.732）。** 380 V 是三相四线制里
**线电压**（两根相线之间），220 V 是**相电压**（相线对中性线）。它们不是两个
"代差"，而是**同一个低压系统的两种接法**。你最初把 LV=220V、MV=380V 并列，
问题就出在这里：作为"等级阶梯"这个跨度太小（只有 1.73 倍），升级感不足。

### 1.3 用电种类（交/直流）

| 种类 | 特点 | 现实用途 |
|---|---|---|
| 直流 DC | 无相位、无功率因数，P=U·I 直接成立 | 电池、电子、电解、HVDC 远距离直流输电 |
| 单相交流 AC | 有相位、有功率因数，可变压器升降压 | 家用 220 V |
| 三相交流 AC | 三相同步、功率平稳、可产生旋转磁场 | 工业电机、电网主干 |
| 变频 / 整流 | 交-直-交 | 电机驱动、HVDC |

**对我们的意义**：完整 AC 潮流的额外复杂度来自相角、功率因数与无功功率；这些仍不进入
玩法。实现采用**功率因数固定为 1 的平衡三相模型**：单相使用 `P=U_phase·I`，三相使用
`P=√3·U_line·I`。三根相线电流大小相等，三相四线的中性线在理想平衡时电流为 0；相序、
相角和无功不建模。这样 `√3` 与三相总线损有真实含义，同时玩家仍不需要解潮流方程。

## 2. 设计目标与范围（建议）

### 2.1 目标

1. **真实但不折磨**：物理量真实（V/A/W/J/Ω），公式真实（单相 `P=UI`、
   平衡三相 `P=√3UI`、每根导体 `I²R`），
   但玩家只需做**选择**（选电压、选缆径、选距离），不需要解潮流方程。
2. **升级有道理**：等级越高 ≠ 无脑更好（同现有设计：高等级待机耗电更大）。
3. **变压器有存在意义**：这是整套系统的灵魂，必须让"升压—输电—降压"成为
   真实收益，而不是可选装饰。
4. **可扩展**：能在其上长出发电机、储能、电网调度、故障保护。
5. **与现有代码平滑衔接**：保留 `EnergyTier` 与端口体系；旧 `Energy` NBT 按
   `1 FE = 1 J` 导入 `JouleStorageModule`，不让旧世界直接丢失电量。

### 2.2 明确范围内 / 范围外

**范围内（本轮设计）**：电压等级、电流、功率、线损、导线、变压器、机器额定电压
与过压行为、发电机与储能的概念位置。

**范围外（后续单独文档）**：电网调度/竞价、复杂故障电流计算、无功补偿、
变频驱动、直流输电的详细模型。

## 3. 核心物理模型

### 3.1 四个基本量

| 量 | 符号 | 单位 | 在本模组中的"地位" |
|---|---|---|---|
| 电压 | U（或 V） | V（伏） | **网络属性**：由电源/变压器决定，不由负载决定 |
| 电流 | I | A（安） | **负载决定**：取决于连接的设备要多少功率 |
| 功率 | P | W（瓦）= J/s | 单相 `P=U_phase·I`；平衡三相 `P=√3·U_line·I` |
| 能量 | E | J（焦） | 功率的积分 `E = ∫P·dt`，缓存里存的就是它 |

> **与 FE 的换算锚点（已定）**：`1 FE = 1 J`。该换算只出现在专用转换器与旧存档迁移；
> 普通机器、储能控制器和电力端口均不暴露 `IEnergyStorage`。

### 3.2 三个"现实但可调"的定律

1. **欧姆定律**：`U_drop = I·R`。求解器显式计算每段导线的电阻压降，作为焦耳损耗的中间量；
   为保持轻量模型，不把该压降继续传播为下游端点电压。
2. **功率公式**：单相 `P=U_phase·I`；功率因数为 1 的平衡三相 `P=√3·U_line·I`
3. **线损（焦耳定律）**：每根载流导体为 `I²R`；平衡三相三根相线合计 `3I²R`

### 3.3 线损——为什么它让系统"活"起来

设要输送总有功功率 `P`。单相的 `R_loop` 是相线与中性线的回路总电阻；三相的
`R_phase` 是每根相线电阻：

```
单相电流      I_1φ = P / U_phase
单相线损      P_loss,1φ = I_1φ² · R_loop

三相线电流    I_3φ = P / (√3 · U_line)
单根相线压降  U_drop = I_3φ · R_phase
三相总线损    P_loss,3φ = 3 · I_3φ² · R_phase
                         = P² · R_phase / U_line²
端到端效率 η = P / (P + P_loss)
```

**结论**：线损与**电压的平方成反比**。同样的功率送同样的距离，把电压提高 10 倍，
线损降到 **1/100**。这就是升压变压器的全部价值，也是唯一的"唯一正确答案"。

**示例（可写进 HUD/手册，帮助玩家"看见"线损）**：
输送 `10 kW`。单相取回路总电阻 `1 Ω`；三相取每根相线电阻 `1 Ω`：

| 输送电压 | 电流 I | 线损 `I²R` | 效率 η |
|---|---|---|---|
| 220 V（单相） | 45.5 A | **2.07 kW** | 83% |
| 380 V（三相） | 15.2 A/相 | 0.69 kW（三相合计） | 93.5% |
| 10 kV（三相） | 0.577 A/相 | 1.00 W（三相合计） | ~100% |
| 110 kV（三相） | 0.052 A/相 | 8.3 mW（三相合计） | ~100% |

一眼可见：**低压送大功率 = 相当一部分的电变成了热**。玩家会自发地"升压再送"。
这里的三相线电流按 `√3` 折算，线损则是三根相线的 `I²R` 之和。模型保留平衡三相的
工程收益，但仍不追踪瞬时波形、相角、相序或无功功率。

### 3.4 三个"要不要投影到游戏"的现实细节（建议取舍）

| 现象 | 现实 | 建议 |
|---|---|---|
| 端点电压传播（U 沿导线逐段下降） | 导线两端电压不等 | **不做**。计算 `U_drop=I·R` 作为损耗中间量，但负载仍使用线路标称电压 |
| 集肤效应（交流走表面） | 交流电阻随频率升高 | **不做**。游戏计算只保留直流电阻 |
| 功率因数 cosφ | 感性负载需更多电流 | **固定为 1**。不引入无功；三相仍使用 `√3` |

**只保留平衡交流的功率/电流换算与欧姆损耗链路**：每根载流导体按
`U_drop=I·R`、`P_loss=I·U_drop`，三相线路汇总三根相线；但不求解沿线端点电压。
这样保留工程意义与可理解性，同时不引入完整潮流方程组。

## 4. 等级阶梯

> **已定（方案 1）**：真正的"代差"是**电压等级**（380 V → 10 kV → 110 kV → 500 kV）；
> **单相 220 V / 三相 380 V 不是两个等级**，而是**同一低压等级内部的接线方式**。
> §4.1 给电压阶梯，§4.2 讲单相/三相接线属性。此前的"220/380 并列""3.3 kV/35 kV
> 路线"草案均已作废。

### 4.1 电压等级（真正的代差）

| 等级 | 线电压 | 现实中对应 | 层级倍数 | 典型相线额定电流 | 平衡三相额定功率 |
|---|---|---|---|---|---|
| **LV** | **380 V** | 低压动力（三相四线，含 220 V 单相） | — | 10–63 A | ≤ 41.5 kW |
| **MV** | **10 kV** | 中压配电干线 | ×26 | ~100 A | ~1.73 MW |
| **HV** | **110 kV** | 高压输电 | ×11 | ~200 A | ~38.1 MW |
| **EHV** | **500 kV** | 超高压主干输电线 | ×4.5 | ~400 A | ~346 MW |

- **倍数关系**：380 → 10000（×26）→ 110000（×11）→ 500000（×4.5）。
  每级 **×4.5 ~ ×26**，代差清晰。
- **电压是全局标称值**：单相用相电压 `I=P/U_phase`；三相用线电压
  `I=P/(√3·U_line)`（§4.2）。
- 数值直接取自中国电网标称阶梯（380 V / 10 kV / 110 kV / 500 kV），
  与现实一致，懂电的玩家一眼就懂。
- LV 覆盖现有"入门到小型工业"的全程；MV 以上才用于**远距离、大功率**，
  与线损/变压器玩法严丝合缝。

### 4.2 接线方式：单相 220 V / 三相 380 V（LV 级内部属性）

**现实电网中，220 V 与 380 V 的关系是 √3，线电压 = √3 × 相电压**——它们是
**同一个低压三相四线系统**的两个面，不是两个循环。这个关系既用于选取标称电压，
也进入平衡三相的功率/电流换算。

**现实分布（决定我们的取舍）**：工业上**绝大多数设备就是 380 V**；只有极少数
大型设备（大型冶炼、电炉等）会上 10 kV / 110 kV；**高压主要用于"传输与发电侧"**，
工业现场常用的中压就是 10 kV。220 V 主要是**民用/小型**。

| 接线 | 取电方式 | 电压 | 典型 |
|---|---|---|---|
| **单相** | 一根相线 + 中性线 | **220 V** | 民用、小型机、照明、控制电路 |
| **三相** | 三根相线 | **380 V** | 工业设备（**绝大多数**） |

**设计后果**：

1. **机器只声明电压等级**（380 V 为主）；**单相/三相是导线与接口的接线属性**，
   不用每台机器都标。
2. **高压（10 kV / 110 kV）服务于"传输与发电侧"**，不用于普通设备——
   这正是变压器存在的意义：**发电/远送用高压，进入工厂前降到 380 V**。
3. **接线方式决定电流公式**：单相使用 220 V 相电压并按 `I=P/U_phase`；三相使用
   380 V 线电压并按 `I=P/(√3·U_line)`。三相四线按平衡负载处理，中性线电流为 0；
   相序、相角和可变功率因数不建模。

### 4.3 接法与故障后果（现实行为）

| 情形 | 后果 | 可恢复 |
|---|---|---|
| **小三相接入大功率设备**（供电电压不足） | **无反应**，提示"电压不足" | 是（改接足够电压即恢复） |
| **三相接成二相 / 缺项**（电机缺相） | **带电缺相持续 40 tick 后爆炸** | 否 |
| 接入更高电压（过压） | 持续 40 tick 后端口爆炸（§8.3、§8.4） | 否 |
| 接入更低电压（欠压） | 无反应 + 提示 | 是 |

- **缺项爆炸威力 = 2 个 TNT**；§8.6 列出的是后续配置规划，当前为代码固定值。
- 注意区分：**欠压 = 无反应不炸**（安全），**缺项 = 炸**（危险）。二者不是一回事。
- 只有当至少一根所需导体由闭合电源带电时才累计缺相确认；未通电的半成品接线不累计。

### 4.4 命名

**等级名与电压一起显示**（已定）。例如物品/界面写 `MV · 10 kV`、`LV · 380 V`。

| 等级 | 显示 |
|---|---|
| LV | `LV · 380 V` |
| MV | `MV · 10 kV` |
| HV | `HV · 110 kV` |
| EHV | `EHV · 500 kV` |

代码与配方仍用 `LV/MV/HV/EHV` 枚举名。这样既保留熟悉的四级简称，又让"电压"
这个新维度在第一眼就被看见——这恰恰是本系统相对 FE 的最大卖点。

## 5. 电网与拓扑

### 5.1 网络（Grid）是什么

**一段连通的导线 + 所有接在它上面的设备 = 一个电网。** 电网有唯一的一个
**标称电压**。

### 5.2 电压一致性规则

**同一电网内的所有导线与设备必须电压匹配**，否则接不上或烧毁：

1. 两台**不同电压**的电网直接相连（不经变压器）→ **非法**。表现为：连不上，
   或（若强行并入）过压损坏。
2. **变压器**是唯一合法的"电压边界"：它的低压侧属于低压电网，高压侧属于
   高压电网，二者通过铁芯耦合，电气上隔离。
3. 机器有**额定电压**：只能接入等于额定电压的电网。接入更高电压 → 过压烧毁；
   接入更低电压 → 无法工作（欠压）。

### 5.3 拓扑与求解（性能关键）

**建议：限制为"单电源树 + 显式变压器边界"，不做通用潮流求解。**

- 每个电网做一个**并查集/DSU**，tick 时增量维护（拆线/放线时合并/分裂）。
- 电网内只允许一个**专用主电源**；第二个主电源会被判为冲突。储能不计作冲突主电源：
  先由主电源满足普通负载，储能仅补足缺口，最后才用剩余功率充电。
- 负载按**树**从源向叶传播：先算总需求 `ΣP`；单相取 `I=ΣP/U_phase`，平衡三相取
  `I=ΣP/(√3·U_line)`，再按各段累计相线电流计算每根导体的 `I²R` 并汇总。
- 放线拒绝相同端点的重复/并联线路，也拒绝会形成环路的连接；v1 始终保持放射状拓扑。
- 只有两端区块均加载的线路参与传输；未加载线路不会被误判为带电缺相。

这样每 tick 的复杂度是电网尺寸的线性，且完全避免了线性方程组。

> 若将来要支持"多源并联/环网"，再考虑迭代潮流；本轮不做，文档留口子。

### 5.4 电气上互不干扰

不同电压、不经变压器的电网**互不相通**。这自然产生了：
- 走线规划（不同电压的线要分开布线）；
- 变压器作为"枢纽"的可建造性；
- 用错等级立刻可见的失败（连不上 / 烧）。

## 6. 导线（缆）设计

> **已定（批注）**：
> - 导线只有**两个独立限制**：**载流量**不够 → 过热 → 冒烟 → 炸毁/断开（§6.10）；
>   **绝缘等级**只决定**触碰时的安全**（§6.11），**不再**因电压超过绝缘而炸线。
> - 本模组的导线**不是 FE 那种"一根线通吃"**，而是**多导体**：一条线路必须**配够根数**
>   （多线/多相）。接地方式是**端子（节点）**，一根端子柱上可以有多个接线位。
> - 柔性导线（软线）按**现实逻辑**建模（端子可在一格内放多根），硬质铜排按**沉浸工程**
>   那种"固定走线"的逻辑。**具体美术资源交给美术**（§6.2）。
> - **软线悬链线下坠只作视觉**；电气长度取**两节点直线距离四舍五入到整数格**（§6.9）。
> - **线缆不分电压等级**：用**载流量**与**绝缘**两个**正交**属性描述（§6.1）。

### 6.1 每根导线的参数

线缆**没有电压等级**。一条 10 kV 线路用什么线，不看"它是不是 MV 线"，
而看**三个互相独立的属性**：

| 参数 | 含义 | 玩家视角 | 违反后果 |
|---|---|---|---|
| `material` | **导体材料**（铜 / 钢芯铝绞线） | 有多重、能架多远、电阻多大 | （不爆炸，决定能否远距离架设） |
| `ampacity` | **载流量**（50 / 150 / 500 / 800 / 1500 / 1600 / 5000 A） | 能通过多大的电流 | 过热 → **冒烟 → 爆炸/断开**（§6.10） |
| `insulation` | **绝缘**（裸线 / 一类 / 二类） | 碰了会不会死 | **只影响触电**，**不影响**能不能接（§6.11） |
| `R_perBlock` | 每格电阻（由载流量档 × 材料推导） | 有多"费电" | （不直接爆炸，只产生线损） |
| `color` | 外皮颜色（16 色染料，**数据**不是物品） | 区分线路 | 无，纯外观（§6.8） |
| `conductors` | 导体根数 | 这条线能走几根 | 少于所需根数 → 连不上/缺项 |

**三个属性为什么必须正交**：载流量是"铜有多粗"，绝缘是"皮有多厚"，
材料是"用什么金属"。把三者捆成"等级"会强迫玩家用 5000 A 的粗线去走 5 A 的控制回路，
也会让"细铜 + 厚皮"这种现实中常见的组合消失。

**材料决定什么**（§6.1.1）：

| 材料 | 电阻系数 | 下坠系数 | 能否有绝缘版 |
|---|---|---|---|
| **铜**（基准） | ×1.0 | ×1.0 | **能**（裸 / 一类 / 二类） |
| **钢芯铝绞线** | **×1.3** | **×0.35** | **不能**（只有裸线） |

**绝缘会降额**（§6.10）：绝缘包住铜就散热更差，所以

| 绝缘 | 载流量系数 |
|---|---|
| 裸线 | **100 %** |
| 一类 | **90 %** |
| 二类 | **80 %** |

不降额的话"好绝缘"就变成纯免费升级，玩家没有理由用裸线。

#### 6.1.1 钢芯铝绞线（ACSR）：为长跨距而生

**它解决什么问题**：铜是最好的常温导体，但**重**。架空线路真正难的不是导电，
是**把线拉过去**——跨距越长，线越重，下坠越大，越容易碰到地面或别的线。
**钢芯铝绞线**（现实中的 ACSR，钢芯铝绞线）用**钢芯承力、铝层导电**，
在同等载流量下重量约为铜的一半，因此**能架得更远、下坠更小**。
全世界的架空高压线几乎都用它，原因就在这里。

| 项 | 铜 | 钢芯铝绞线 | 为什么 |
|---|---|---|---|
| 电阻 | 基准 | **×1.3（更费电）** | 铝的电阻率约为铜的 1.6 倍，且钢芯不导电，同等载流量下金属截面更小 |
| 下坠 | 基准 | **×0.35（更直）** | 轻一半，且钢芯允许更小的弧垂 |
| 绝缘版本 | 裸 / 一类 / 二类 | **只有裸线** | 见下 |
| 规格 | 50 / 150 / 500 / 1500 / 5000 A | **800 A / 1600 A** | 用于比 500 A 更远、比 1500 A 更远的跨距 |

**为什么没有绝缘版**：不是数值平衡，而是现实如此——没有哪条架空线会去给导体加绝缘，
加了绝缘它既重又硬，那还不如用铜。所以钢芯铝绞线**永远是裸线**（§6.11 一律按裸线判触电），
玩家买它就是在买"能架远"，而代价是**这条线路必须避开人的活动区**。

**两个规格为什么卡在铜的档位之间**：800 A 落在铜的 500 A 与 1500 A 之间，
1600 A 略高于 1500 A。它们不是"更大的导体"，而是**另一条产品线**——
选它是因为**跨距**，不是因为想要更大的数字。所以它们**不需要**压过铜的阶梯。

**收益是"能建"，不是"更好"**：同样载流量下钢芯铝绞线**更费电**，
只有当距离长到"铜线根本架不过去"时，它才划算。这个取舍是刻意的。

**渲染上必须能一眼认出来**：钢芯铝绞线未染色时是**亮铝色**而不是黑色，
因为它本来就没有外皮。染了色之后照常显示染料色 — 颜色始终是标记，不是材料。

### 6.2 两类导线与美术分工

| 类别 | 原型 | 走上逻辑 | 美术 |
|---|---|---|---|
| **硬质导线（铜排 / 母线）** | 沉浸工程式：固定方块、贴墙、直角、可并排堆叠 | **方块化**：直接以方块占位与连接 | 固定模型，随等级变粗 |
| **柔性导线（软线）** | 现实式：沿端子走向、有不同规格、会下坠 | **端子 + 连线**：一格内多个端子位 | 端子柱 + 悬链线缆 |

- **端子是节点**：软线由**端子**构成连接点。端子同时也是**电网节点**——
  可以**分线**接入机器，也可以**分方向继续延伸**（像现实的配电节点）。
- **规格（截面积）决定载流量与电阻**；软线有不同规格档位（越粗越贵越强）。
- 两类都能构成电网；玩家按场景选用。

> **美术资源交由美术**：端子的外观（随等级变大、变高，如绝缘子柱），
> 硬质铜排与软线的模型/贴图，全部按占位美术流程走（见
> `docs/textures-placeholder-manual.md`）。本文只定**行为与规格**，不约束外观。

### 6.3 端子（Terminal）：端子座 + 端子，网格自由布置

**端子由两部分组成**：**端子座**（架子）和**端子**（装在上面的铜柱）。
端子座自己**不是电气节点**，它只是提供一个规则网格，玩家在网格里**自由选择位置**放置端子；
**每个端子才是独立的端位、也是独立的电网节点**。

#### 6.3.1 网格密度按等级递减

端子座按等级提供不同的网格，**等级越高、端子越大、能放的位置越少**：

| 等级 | 方块内网格 | 端位数上限 | 典型接线 |
|---|---|---|---|
| **LV（220V/380V 共用）** | **4 × 4** | **16** | 一格最多 16 个独立端子 |
| **MV（10 kV）** | **2 × 2** | **4** | 端子变大，位置减到 4 个 |
| **HV（110 kV）** | **1 × 1** | **1** | 一格一个 |
| **EHV（500 kV）** | **1 × 1** | **1** | 一格一个 |

> **规则变更**：旧规则"一格最多 4 根导体（10 kV 及以下）"**已作废**。
> 现在 **LV 一格最多 16 个端子、16 个独立节点**；相序本来就不建模，故无冲突。
> HV / EHV 的端子座只有一个端位；一个三相三线设备端口要在设备的三个可用面上各装
> 一块端子座，求解器会把这三块单端子座聚合成同一个三相端口。

#### 6.3.2 放置与拆除

| 操作 | 手持 | 行为 |
|---|---|---|
| **放置端子座** | 端子座物品 | 放下一个**空的**端子座（架子），自带 0 个端子 |
| **装一个端子** | 端子物品 | 右键端子座的**某个格子** → 该格长出一颗端子 |
| **拆单个端子** | 空手 + Shift | 右键**指着的那个格子** → 拆下那一颗，掉"端子"物品 |
| **整块挖掉** | 非安装工具的镐 | 方块被破坏，**底座与端子散开掉落**（各掉各的物品） |
| **整块完整取下** | **安装工具 + Shift** | 端子座连同上面的端子一起**完整取下**（物品形态入包） |

- **端子座放下时是空的**：像架子一样，专门往上放端子；没有端子时它只是一个无电气的结构方块。
- **每个端子都是独立端位、独立电网节点**：允许分线接入机器，也允许分方向继续延伸。
- 网格位置**自由选择**：不要求按顺序填，玩家想放哪格就放哪格。

**拆掉任何东西，线缆都必须"两端一起消失"**（重要，曾经出错）：

| 操作 | 线缆的结局 |
|---|---|
| 拆单个端子 | 该端子上所有线缆**整条**掉物品：先清本座记录，再清**远端座子的那一半** |
| 挖掉端子座 | 座上所有线缆**整条**掉物品，同样清远端 |
| 完整取下端子座 | 同上 |

- 每根线以规范化端点对 `CableRunId` 唯一标识；线径、绝缘、颜色与热状态都是记录属性，
  不参与电气身份。剪线、染色和拆端子直接修改维度级权威数据，即使远端区块未加载也能完成。
- 已加载端子座的方块实体只缓存本地渲染/求解所需记录；重新加载时从权威数据重建缓存。
- 旧存档的双端 `Cables` NBT 首次加载时去重导入。删除记录同时建立 tombstone，防止尚未加载的
  旧端点稍后把已删除线路再次导入并“复活”。

#### 6.3.3 朝向

- **网格只开在一个面上**（像配电盘）：另外五面是空白外壳。
  这样模型简单、格子判定明确，也符合"端子座是装在表面上的架子"的直觉。
- **`FACING` 的语义是"背板贴着哪一面"**（= 被点击的那一面的方向），**铁律**：
  背板永远在 `FACING` 那一侧；端子从背板立起来，**朝方块外面**伸出去
  （像电气柜上的支柱绝缘子，不是往柜子里塞）。
  这一句同时约束四个地方，任何一处理解反了就必然错：
  1. **方块模型**：`facing=north` 的背板在 `z = 0..1`（贴着 z 小的一侧）；
  2. **碰撞箱 `getShape`**：薄片贴在 `FACING` 那一侧；
  3. **格子判定 `cellFromHit`**：命中点投影到**网格所在的那个面**；
  4. **BER 渲染**：脚放在背板表面，端子生长方向 = **`FACING` 的反方向（朝外）**。
   - **历史教训（这条规则被改写四次，前三次都是错的）**：
     - 第一版："`FACING` = 网格指向的方向"。背板被放到方块**背离墙的那一侧**，
       整个端子座悬在空中、和墙面之间留着一条缝——玩家报告的"全反了"。
     - 第二版：模型按旧约定生成，`getShape` 却按另一套写，六个朝向里有**四个**
       （west / east / up / down）模型和碰撞箱分居两侧。
     - 第三版：背板位置终于对了，但端子被设计成**朝方块内部**生长。背板是整面实心的，
       端子整个被埋进方块里，玩家什么都看不见；后来又给脚的位置取反符号，端子干脆从
       对面钻出去，于是报"延伸方向反了"。
     - 现在：**背板贴 `FACING` 侧、端子朝 `FACING` 的反方向凸出**。四个使用方全部按此实现，
       并由校验脚本逐朝向核对；脚本直接读源文件里的基向量表，不手抄数字。
- **六向各面背板位置与端子生长方向**（任何改动都必须同时改这四处）：

| `facing` | 背板位置 | 端子生长方向 | 背板碰撞箱（读模型） | 墙面朝向 `up`（屏幕上方） |
|---|---|---|---|---|
| north | `z 0..1` | `+z`（朝房间） | `z 0..d` | `+y` |
| south | `z 15..16` | `−z`（朝房间） | `z 1−d..1` | `+y` |
| west  | `x 0..1` | `+x`（朝房间） | `x 0..d` | `+y` |
| east  | `x 15..16` | `−x`（朝房间） | `x 1−d..1` | `+y` |
| up    | `y 15..16`（天花板） | `−y`（朝房间，朝下） | `y 1−d..1` | `+z` |
| down  | `y 0..1`（地面） | `+y`（朝房间，朝上） | `y 0..d` | `−z` |

  - `d` = 该等级背板厚度（1/16 方块制）：LV `1/16`、MV `1.5/16`、HV `2/16`、EHV `2.5/16`，
    由 `TerminalPlateShapes` 直接读 `models/block/<级>_terminal_mount_<朝向>.json` 的
    `elements` 得到，**代码里不再有厚度常数**。改方块模型即改碰撞箱。
  - west / east 最容易写反：west 是 −x 一侧，所以背板在 `x = 0`、端子朝 `+x`；
    east 背板在 `x = 16`、端子朝 `−x`。up / down 同理：up 背板在 `y = 16` 朝下，down 背板在 `y = 0` 朝上。
  - **同侧是硬要求**：碰撞箱和模型背板必须落在方块的同一侧。
  - **生长方向恒为"背板所在侧的反方向"**，这是"朝外凸出"的唯一判据；
    不要用"朝方块内部"或"朝玩家"这类描述，它们在不同朝向下会自相矛盾。

#### 6.3.4 格子判定

- 右键时用**命中点**换算到网格格坐标：网格面 → 该面上的 2D 坐标 → 取整到格子。
- **u / v 两个轴对六向都要有定义**（由渲染器的摆放公式反解得到，见 §6.3.3）：
  - north：`u = x`，`v = y`
  - south：`u = 1-x`，`v = y`
  - west：`u = 1-z`，`v = y`
  - east：`u = z`，`v = y`
  - up（天花板）：`u = x`，`v = z`
  - down（地面）：`u = x`，`v = 1-z`
  - 推导：渲染器把格子放在 `0.5 + right*(u-0.5) + up*(v-0.5) − normal*7/16`，
    反解 `u = 0.5 + (p − 0.5)·right`。因为每个 `right`/`up` 都是带符号的世界坐标轴，
    结果只可能是 `coord` 或 `1 − coord`——**取哪个号完全由 `right` 的符号决定**。
    north 的 `right = (+1,0,0)`，所以 `u = x`；south 的 `right = (−1,0,0)`，所以 `u = 1−x`。
    改基向量表就必须同步改这里，否则点到的格子和画出来的格子会错开。
  - 校验方法：把每个朝向的 16 个格子中心按渲染公式算出来，再代回**独立写出的** u/v 公式，
    必须回到同一个 (col,row)。六个朝向 × 16 格全部往返一致才算通过（脚本 `DeriveUV2`）。
- 旧版只实现了四个墙面分支，地面/天花板直接返回 −1 → 提示"点在网格外了"、
  实际上永远装不上去。**判定和渲染必须共用同一张基向量表**，否则点击落在别的格子。
- 每个格子的占用状态存在方块实体里（`Set<cell>`），**属性不随端子数量增长**
  （否则 16 格要 2^16 个方块状态，不可行）。
- 方块状态**只保留 `facing`**（等级由 Block 实例携带，不做成属性——做成属性会要
  6 朝向 × 4 等级 = 24 个变体，而每级只有自己那 6 个模型，其余 18 个会刷 `missing model for variant`）；
  端子的有无与位置**全部由方块实体记录并同步**。
- **碰撞箱（`getShape`）也要六向各一份**：背板贴哪面就薄在哪面，厚度按等级读模型。
  旧版 up / down 落到 `default` 分支返回整块（`Shapes.block()`），
  于是地面上的端子座把玩家顶在方块外、天花板上的挡住视线和点击。

#### 6.3.4a 端子碰撞盒（包裹模型的轴对齐盒子）

**需求**：端子放上去后要有碰撞体——玩家会被挡住、瞄准射线会打在它身上，
从而在拉线 / 拆放时能看出有没有对准，走路时也会撞到。

**做法**：盒子 = **背板形状 ∪ 每颗端子的包围盒**，两者都从资源文件算，代码里没有尺寸表。

| 部分 | 数据来源 | 解析位置 |
|---|---|---|
| 背板 | `models/block/<级>_terminal_mount_<朝向>.json` 的 `elements` | `TerminalPlateShapes` |
| 端子 | 该样式 `.obj` 里**被 `f` 引用到的顶点**的 min/max，再套摆放配置 | `TerminalModelBounds` + `TerminalPoseReader` + `TerminalPoser` |

- **端子包围盒**：只统计被面引用的顶点，导出残留的孤立点不会把盒子撑大；
  但如果把装饰性细线画在离主体很远的位置，盒子会一直包到那里（"最小矩形"的必然结果）。
- **变换必须与渲染器一致**：`TerminalGeometry#placeBox` 复刻 `TerminalMountRenderer`
  的 pose 顺序（foot → 面基 → offset → −origin → rotation → scale → mirror），
  八个体角各变换一次再取新的 AABB。两处必须同时改，否则碰撞盒会与画出来的端子错位。
- **为什么服务端自己解析**：碰撞盒在**服务端**被查询（移动、视线、点击），
  而烘焙后的 OBJ 只存在于客户端。用客户端的烘焙结果在单人下"碰巧能用"，
  专用服务器上会静默退化成兜底盒——这是只在发布后才暴露的典型坑。
  因此 `TerminalModelBounds` / `TerminalPoseReader` **直接读资源包文本**，两侧同源。
- **始终用服务端的资源包**：避免客户端资源包（可替换方块模型）与服务端判定不一致。
- **空座只留背板**，不是实心方块；拆端子后碰撞盒立即失效。
  为此 `TerminalMountBlockEntity#sync` 额外调用 `level.setBlocksDirty(...)`：
  装/拆端子只改方块实体、不改方块状态，不刷脏则服务端会一直用旧的形状缓存，
  出现"自己穿模、别人的客户端撞得到"。
- **不影响选格与拉线**：`cellFromHit` 仍按世界坐标投影选格，
  射线打在端子外壳上照常解析到该端子所在格子。
- **缓存**：`TerminalModelBounds` / `TerminalPlateShapes` / `TerminalPoseReader` 按
  (样式, ResourceManager 标识) 缓存；整座架子的合并形状再按
  (等级, 朝向, 已装端子集合) 缓存一层。服务端资源重载时三者全部清空。

#### 6.3.5 拉线交互（连接两个端子）

| 操作 | 行为 |
|---|---|
| **手持线缆 + 右键**某颗端子 | **接线 / 移动线头**（从「当前线头」连到这颗端子，消耗手上 1 个） |
| **空手 / 其他物品 + 右键**某颗端子 | **只拿起或移动线头**，不成线 |
| **空手 + Shift + 右键**某颗端子 | **拆下那一颗**（见 §6.3.2），连着的线一起掉 |
| **手持线缆 + Shift + 右键**某颗端子 | 仍然是**接线**（接线手势优先于 Shift） |

- 一次点击只做一件事：要么**移动线头**，要么**真的接线**。
  第一次右键是"拿起线头"，手持线缆再右键另一个端子才成线。
- **拿端子不会拉线**：手上是端子时右键格子只会装端子，不会产生线头。
- **一个端子的接线数量不限**：可以接任意多根。现实中一个接线柱上并几根线也是常态，
  而且限制数量只会逼玩家去放一堆本不需要的端子。
- **规格由手持物品决定**：服务端读玩家手上的线缆，决定这条线是几安、什么材料、什么绝缘，
  并且**只扣手上那一叠 1 个**。手上没有线缆就**不能成线**。

#### 6.3.6 实现落点

- **每级注册 1 个端子座方块** + **1 个端子物品**（不是按端位数分 4 件了）。
- **端子按"样式"独立，不按电压等级共用**：端子物品携带的是 `TerminalStyle`
  （`lv_terminal` / `mv_terminal` / …），不是 `EnergyTier`。
  样式同时决定三件事：**能装进哪种端子座**（`tier`）、**用哪份 OBJ 与摆放配置**
  （`model`）、**物品注册名**（`itemName`）。
  这样同一个电压等级以后再加第二种端子（母线夹、瓷瓶、树脂绝缘子）时，
  只需在 `TerminalStyle` 里加一个常量 + 一份 OBJ + 一份
  `models/terminal/<样式id>.json`，**渲染器与线缆代码都不用改**，
  也不会出现"后加的把先前的模型数值覆盖掉"。
  存档里记样式 id（NBT 键 `Style`）；旧存档的 `Tier=lv` 由 `TerminalStyle#fromSaved`
  映射到 `lv_terminal`，读入后照常显示，下次保存转成新格式。
- 端子座方块带方块实体：记录 **已占用的格子集合**、每格的端子样式（后续接线用）。
- 方块状态属性：**只有 `facing`**（背板贴哪一面，**六向**）；等级由 Block 实例携带。
- **视觉实现**：
  - 端子座本体 = 方块模型（只有一块背板，**不再画格线和铜座**——空座一眼就能看出是空的，
    装上的端子完全由 BER 画，不会和占位铜柱混在一起），六向各一份、坐标已旋转好；
  - 端子 = **OBJ 模型**（`neoforge:obj` 加载器，每样式一份 `.obj` + `.mtl` + 两张贴图：
    瓷体与金属帽），由 BER `TerminalMountRenderer` 按格子摆放；
  - 端子的**偏移 / 旋转 / 缩放 / 原点 / 锚点**不进代码，由 `models/terminal/<样式id>.json`
    配置（美术改文件 + `F3+T` 即生效，见 `docs/obj-model-manual.md`）。
    **模型姿态与线缆锚点完全分离**：`offset/rotation/scale/origin` 只管模型，
    `anchor` 只管线缆从哪里出来，各有一套数值，互不推导（用户明确要求）。
    理由是端子会反复重导出，而线缆要接的那一点是固定的电气位置，绑在一起会互相拖拽。
  - **`offset` 在朝向旋转之后应用**，所以它的三个数在六个朝向上含义一致：
    `x` 沿脸面向右、`y` 沿脸面向向上、`z` 出板朝房间。
    早期版本把 `offset` 放在模型自身的 north 坐标系里、旋转之前应用，导致贴在东西墙上时
    `z` 会横向推、贴在地面/天花板上时 `z` 会竖向推——这就是"改 `lv.json` 没效果"的真因，
    与文件加载无关（加载链路一直正常，日志无 `Model config ... unusable`）。
  - **摆放配置以「格」为单位（1.0 = 一整格 = 1 米 = 1000 mm）**，与建模软件的毫米标尺一致。
    `offset / origin / anchor / mirrorOffset` 全是格；`scale` 是**纯倍率**（`1.0` = 按 OBJ 原样，
    `0.5` = 一半），**不承担单位换算**——曾把它设计成"多少 OBJ 单位构成 1 格"（默认 `16`），
    结果 `scale: 1.0` 被解释成 1/16 倍，配错默认值后端子放大了 16 倍，属于"一个字段两种含义"的坑，已撤销。
    **OBJ 顶点单位改由 `objUnitsPerBlock` 声明，默认 `1000`（毫米）**：
    本项目模型一律以毫米建模，`1000 mm = 1 格`；`16` 仅用于极少数按原版方块模型标尺
    （方块跨度 `0..16`）绘制的旧文件。该字段只影响顶点的换算，**不影响配置里的数字**；
    此前写死在渲染器里的 `OBJ_UNIT = 1/16` 已移除。四份占位 OBJ 的顶点已同步换算为毫米
    （高度 `625 mm`，与原 `10/16` 格等值）。
    旧配置（1/16 单位）把 `offset / origin / anchor / mirrorOffset` 除以 16 即可迁移（`scale` 不变）。
  - **锚点坐标系：以「模型原点」为原点**，`x` 右 / `y` 上 / `z` 出板，单位**格**；
    默认 `(0, 0, 0)` 就是模型原点（OBJ 自己的 `(0,0,0)`，即柱子底部中心、贴在背板朝房间的那一面）
    ——**数值为零即原点**，这是用户明确要求的不变量。
    - **取值方式**：项目统一用毫米建模，`毫米 ÷ 1000 = 格`。接线点离根部 `500 mm` 就写 `y: 0.5`；
      美术量到多少填多少，不必再"一点点试"，也不必关心 OBJ 顶点单位。
    - **为什么不用方块中心**：方块中心在建模软件里**不显示**，且它与模型根部之间还差一个背板厚度
      （LV 背板 `1/16`、HV 背板 `2/16`，各等级不同），美术无法凭直觉换算。这正是"anchor 不生效 /
      不是模型原点"的根源。模型原点是美术唯一能在编辑器里直接看到、直接点到的点。
    - **修复记录**：更早的实现先加**格子中心**（`+0.5,+0.5,+0.5`）再叠板面退让，`(0,0,0)` 落在方块角上，
      `+1` 才等于移动一整格；对直径不足 `0.1` 格的线而言肉眼几乎不可辨——这是"`anchor` 填了数字
      没反应"的另一半原因（加载链路本身一直正常，日志 `Loaded 4 terminal pose file(s)` 可证）。
    - **多格端子**：每个格子有**自己**的模型原点（该格里端子的根部），`anchor` 对每一格含义完全相同，
      无需任何逐格补偿项。
    服务端也需要锚点（接线距离、点击判定都在服务端），所以数值来源由客户端启动时
    注入 `TerminalGeometry.setAnchorSource(...)`；专用服务端没有这份表时退回 `(0,0,0)`
    （即模型原点），保证 `energy/` 包不依赖 `client/` 包。
  - 端子的**物品 id 必须与资源文件名一致**：`TerminalStyle#itemName` 同时决定
    `models/item/<物品id>.json`、语言键 `item.stardustindustry.<物品id>`。
    曾因 `itemName` 留成裸等级名 `lv` 而资源文件叫 `lv_terminal`，导致物品栏显示品红黑格
    （missing model）+ 未翻译的键名 `item.stardustindustry.lv`；现统一为
    `lv_terminal` / `mv_terminal` / `hv_terminal` / `ehv_terminal`。
  - 端子的**物品形态**是 **16×16 二维图标**（`models/item/<样式id>_terminal.json`，`item/generated`
    + `textures/item/terminal_<样式id>.png`），与 `crushed_iron` 等物品同一套约定。
    **不要让物品直接复用端子 OBJ**：OBJ 走的是 GUI 特化变换链，最终大小取决于模型自身尺寸，
    实测会撑到格子之外（"物品栏里特别大一个"）。图标由 PNG 决定，美术换图即可，与 BER 互不影响。
  - 端子的**尺寸由美术决定，引擎不缩放**：BER 只做 OBJ 单位 → 方块的换算（`×1/16`）
    再乘配置里的 `scale`（纯倍率，默认 `1.0`），除此之外**不做任何自动适配**。
    早先版本会按"格子可用宽 ÷ OBJ 宽"和"剩余深度 ÷ OBJ 深"取较小值自动缩放，
    已按项目负责人要求移除——理由有两条：一是自动缩放的结果取决于模型的**长宽比**，
    没人能凭直觉预测（占位件 `5.6` 宽、`10` 长的柱子就被压到格子宽度的 1/9，
    在 4×4 网格里只剩不到一个像素）；二是"模型多大"本就应该由美术在 OBJ 里直接表达。
    保持端子不超出格子的责任因此转到美术侧，手册 §3.6 给出了每级格子宽度与可用净长。
  - **OBJ 顶点单位就是 1/16 块，但引擎不会自动替你换算**：NeoForge 的
    `ObjModel.parse` 原样保存 `v` 行，而 `neoforge:obj` 包装模型没有 `transforms`，
    所以写了 `z 10` 的顶点在烘焙结果里就在**10 个方块**之外，不是 10/16。
    渲染器因此**必须**自己乘 `1/16`（`UNIT`）。这一条曾经反过来把端子放大 16 倍：
    那次是把"块单位"的格子尺寸和"OBJ 单位"的模型尺寸混着除，得到 3.3 格宽、伸出相机外的大白片。
  - 端子的 **OBJ 原点 = 模型底部中心**（局部 `(0,0,0)` 在脚底，沿 `+z` 长出，截面关于 `x=y=0` 对称）。
    **不要在 OBJ 里烘焙 7/16 的贴面距离**：渲染器已经把脚放在离方块中心 7/16 处，
    顶点再写一次就叠成 14/16，端子会被推出方块近一整格。
  - 占用状态不进方块状态（4×4 有 2^16 种组合），也不进模型；BER 每帧按方块实体数据画。
  - 资源重载时清空 OBJ 缓存，重新导出的 `.obj` 直接生效。
  - **端子 OBJ 必须显式注册烘焙**：NeoForge 只烘焙"被引用过"的模型（blockstate 变体或物品模型）。
    端子的 OBJ 两者都不是——端子座的 blockstate 指向背板模型，端子**物品**是 16×16 图标——所以
    `models/block/terminal_<样式>.json` 默认**不会进入烘焙表**，BER 查到的就是 missing model，
    于是端子数据明明写进了方块实体、画面上却什么都没有。解法是在
    `ModelEvent.RegisterAdditional` 里用 `ModelResourceLocation.standalone(...)` 遍历
    `TerminalStyle.all()` 逐个注册。**这个事件是 MOD 总线事件**，因此 `TerminalMountRenderer` 必须带
    `@EventBusSubscriber(modid = ..., value = Dist.CLIENT)`；缺这个注解时注册方法根本不会被调用，
    而且不会有任何报错——BER 只是安静地跳过。渲染器在模型缺失时按样式各警告一次，
    `latest.log` 出现 `Terminal model ... did not bake` 就是这条链断了。
- **挖掉 vs 完整取下的掉落规则**：
  - 镐挖 → `getDrops` 返回 **1 个空端子座 + N 个端子**，**座上连着的线缆整条掉落**；
    线缆连接**两端一起清**，远端记录不会把线"复活"；
  - 安装工具 Shift+右键 → 把底座和端子**打包进玩家背包**（不落地），线缆同样整条掉落。
- **与 Create 电力学对照**：

| 方面 | Create 电力学 | 本模组 |
|---|---|---|
| 端子形态 | 整体（单一/双重/三重/四重） | **端子座 + 可自由摆放的单个端子** |
| 一格端位上限 | 4 | **LV 16 / MV 4 / HV 1 / EHV 1** |
| 旋转 | 扳手/工具 | **安装工具**循环网格面朝向 |
| 多导体 | 是 | 是（§6.4） |

### 6.4 多导体：一条线不是一根

**这是与 FE 的根本区别。** FE 里"一根线"就能送任意功率；本模组里，
**一条线路由多根导体组成，必须配齐根数**。

- **三相设备**需要 **3 根**导体（三相），**三相四线**需要 **4 根**（含中性线）。
- 三相负载按**理想平衡**处理：三根相线电流大小相等；四线制的中性线必须接全以满足
  接线完整性，但正常平衡运行时其中性线电流与线损为 0。
- **单相设备**需要 **2 根**（相线 + 中性线）。
- **缺项**（§8.2）就是"该 3 根只接了 2 根"；只有已接导体由闭合电源带电时才累计，
  连续 40 tick 后才进入爆炸路径，未通电的半成品接线不会爆炸。
- **一个端子引一根线**：要 3 根就在端子座上放 3 个端子，想并行再加端子——
  端子座网格就是给这个用的（§6.3）。
  这是**电气**上的约定（一个端子 = 一条导体路径）。物理上端子**不限制接线数量**：
  一个接线柱并接几根线是常态，并上来的线视为**同一个节点**（§6.9.2）。
- **相序简化，不建模**：只要求**三根接上即可**（见 §6.5）。
- 想扩容 = **在端子座上多放端子**，或**换更粗规格**。

**设计收益**：电网不再是一个抽象的"点对点连接"，而是**可见的、需要铺设的导体束**。
"布线"本身成为玩法（走线规划、根数配比、转角），缺项故障也有了物理依据。

### 6.5 相序：简化，不做

- **不建模相序**（不区分正序/反序）。原因：本模组的设备是**作为机器整体输入**，
  不存在"单独接电机导致反转"的场景，建模相序只会给玩家一个看不见、难提示的排列问题。
- **只判定根数**：够（3 根三相 / 4 根三相四线 / 2 根单相）= 正常；不够 = 缺项（§8.2）。

### 6.6 多芯线缆（Multi-core Cable）

**概念**：把多根导体**封装进同一条线缆**，一根线走多芯，布线**简洁很多**
（取代"三根并排各拉一遍"）。

- **接入方式二选一**（机器侧，细节在具体机器时定）：
  - **三线独立接入**：每相一根，各自接到自己的端子；
  - **多芯线缆接入**：一根线缆内含多芯，一次接好整组。
- **多芯线缆有专用节点**（**只有一种**）：
  - 节点用于**固定**线缆；
  - **只能直通，不能分多路**——想分路，必须用**端子**（§6.3）或**专用配电箱**。
  - 这样多芯线缆是"点对点的简洁通道"，分线/配电交给端子与配电箱，职责清晰。
- 多芯线缆的芯数、绝缘等级、载流量按 §6.12 规格；**绝缘与载流量规则同单芯**
  （§6.10）。

### 6.7 线槽（Cable Tray）

**用途**：把大量线缆**收进一条槽**里走，整洁且省心。

| 属性 | 设定 |
|---|---|
| 占地 | **一格** |
| 外观 | **连接材质**（连成一条槽） |
| 放置 | 可**贴墙**或放在各种位置，**但开口朝上** |
| 容量 | **最多 32 根**线缆 |
| 内容 | 可放**各种线缆**（不同等级/规格混装） |

**连接流程**（按你的描述）：

1. 线缆先连接到**端口或节点**，**右键开始连接**；
2. 再**右键线槽的入口** → 完成**输入连接**；
3. 然后**在期望的线槽出口右键选择**；
4. 再**连接另一个节点或端口** → 完成这条"穿槽线"。

- 效果：线缆"钻进"线槽、从期望的出口出来，**中间段被隐藏/收束**，
  既整洁又不牺牲电气连续性。
- 线槽**不改变**线缆的电气参数（绝缘/载流量/电阻仍按线缆本身），只是一个**走线通道**。

**进槽线缆的电气长度**（线损按此长度算）：

- **三段相加**：
  1. **端子 → 线槽入口**
  2. **线槽入口 → 出口**（沿线槽内的路径）
  3. **出口 → 端子**
- **每段四舍五入到整数格**，三段**相加**即为该线缆的**消耗长度**。
- 与 §6.9 一致：**不进槽**的线缆按两点直线距离算；**进槽**的线缆按三段之和算。
- 线损按此长度结算：`R = R_perBlock × 消耗长度`（§6.12）。

### 6.8 线缆上色（区分线路）

**问题**：线缆一旦密集——尤其**进了线槽**、或多组线缆并排时——玩家**很快就会搞乱**，
分不清**哪根通到哪台机器**。

**解法**：**线缆外皮可上色**——**颜色是线缆自身的数据，不是物品变体**；
默认是**未上色**（绝缘线显示灰外皮、裸线显示导体本色），玩家用**染料右键已铺设的线缆**给它上色。

| 属性 | 设定 |
|---|---|
| 上色时机 | **铺设后**，手持染料右键线缆；**每次消耗 1 个染料** |
| 颜色数 | 完整染料调色板（**16 色**） |
| 默认色 | **未上色**（`CableColor.UNDYED`，哨兵值 `-1`），不是某个具体颜色 |
| 未上色看起来像什么 | **绝缘线：灰色外皮 `#8C8C8C`**；**裸铜：铜色 `#B87333`**；**钢芯铝绞线：铝色 `#B8BEC4`** |
| 裸线可否染色 | **不可以**。裸导体没有外皮可染，颜色就是它材料本身的颜色 |
| 存储位置 | **写进权威线缆记录**（`CableConnection.color`），由维度级 `ElectricalNetworkSavedData` 存读档；已加载端子只同步渲染缓存 |
| 作用 | **纯标识**：区分线路、方便排查 |
| 对电气的影响 | **无**——绝缘/载流量/电阻/根数/缺项判定**都与颜色无关** |
| 可见位置 | 线缆本体（线槽内由线槽开口露出） |

- **为什么默认是"未上色"而不是某个颜色**：默认黑色在暗处与线缆阴影完全融在一起，
  玩家根本看不出那里有一根线。存"未上色"而不是把灰色/铜色烧进记录，还带来一个好处：
  外观永远由**产品本身**决定，旧存档里写错颜色的线也不会出现"铜线是灰的"这种矛盾。
- **裸线不可染色是设计，不是遗漏**：线的金属色是玩家分辨"这是裸线，碰了会死"
  （§6.11）的**唯一视觉线索**。允许染色就等于把这个线索抹掉。三层拦截：
  客户端 `handleCableEdit`、服务端 `ModNetwork#handleCableEdit`、`CableService#recolor`；
  伪造包也染不了裸线。

- **为什么颜色不做成物品**：15 种规格 × 16 色 = 240 种物品，全部电气相同，
  创造栏和 JEI 会被灌满而毫无意义。颜色做成数据后，**一种真实产品一个物品**，
  玩家想给哪根线换色就换色，不影响库存。
- 上色**必须服务端校验**：服务端不信任客户端上报的颜色，而是检查玩家手上**真的拿着**
  对应颜色的染料，颜色取自**染料物品本身**。伪造包最多能把一根线染成他手上有染料的颜色。
- 目的：让"**这根线通到哪**"一眼可辨，是**线槽内多线混装**时必需的辅助手段。
- 颜色**不参与**任何电气逻辑。

**剪线**：**双手都空**时右键线缆即可剪断，线缆按原规格回到背包。因为一个端子现在能接多根线，
"拆线"不能再靠"拆端子"，必须能单独拆一根。剪下来的线缆**保留原来的颜色**。

> 早先的规则是"空手右键就剪"。这有个陷阱：玩家把线盘放在副手、主手空着去点端子接线时，
> 瞄准射线常常**先擦过一根已有的线**，于是那次本该是"接线"的点击把旧线剪掉了。
> 现在的规则是：**任意一只手拿着线缆，就只可能是"接线"，绝不会是"剪线"**。

### 6.9 软线的走向与悬链线

- 软线连接两个端子/节点，**自然下坠**：使用**最简单的悬链线**即可，
  **不引入复杂物理或锚点求解**。
- **下坠纯视觉**：不影响电气参数。
- **电气长度**取**两端节点直线距离，四舍五入到整数格**——
  即损耗按"格数"算，与 §6.12 的 `R_perBlock × 格数` 一致，简洁可预期。
- **进槽线缆另算**：穿过**线槽**的线缆按三段之和计算（端子→入口 + 入口→出口 + 出口→端子），
  见 §6.7。

#### 6.9.1 线缆是「连接」，不是「方块」（已实现）

线缆**没有方块形态**：不占格子、没有方块状态、没有碰撞箱。它是两个端子之间的一条数据，
和"端子是节点"这一设定完全一致——**节点长在端子上，线只是把节点连起来**。

**存储位置：每维度一份 `ElectricalNetworkSavedData`。** `CableRunId` 只由规范化端点对组成，
所以相同两端不能因线径、绝缘或颜色不同而产生并联副本。权威记录保存产品属性、颜色、热量、
最后更新时间、能量换算余数、数据版本与迁移状态；端子方块实体只保留已加载区域的渲染/求解缓存。

所有增删、染色和迁移都必须走 `CableService`。服务层先改权威记录，再刷新当前已加载的端子缓存；
未加载远端不阻止剪线、染色或拆端子，也不会被强制加载。旧版双端 NBT 在端子首次加载时导入，
tombstone 的优先级高于迟到的旧记录，因此已删除线路不会复活。未加载线路暂停传输，热状态则按
世界经过 tick 有上限地冷却；退出重进不会清空过热状态或故障确认。

**渲染归属：由持有较小端点（`a`）的一端绘制。**
两个已加载端子缓存都能看见同一权威记录，若两边都画，线会被**画两遍**（亮度加倍、重叠处出伪影）。
`CableConnection` 在构造时就把两端排成固定顺序，所以"谁画"是确定的，
与玩家从哪一端拉起无关。

**裁剪：渲染器必须扩大包围盒。**
方块实体渲染器默认只按**自己那一格**做视锥裁剪。线缆动辄跨越几十格，
不扩大包围盒的话，端子座一方出屏，整根线就**凭空消失**——看起来像线被删了。
`TerminalMountRenderer` 因此把包围盒扩到所有线缆远端，并开启 `shouldRenderOffScreen`。

**几何只有一份实现：`TerminalGeometry`。**
端子的脚点 = 格子中心沿面板投到**背板内表面**（离方块中心 `7/16`），
这个点同时被**端子渲染器**（画柱子）、**线缆渲染器**（挂线头）和**交互代码**（拾取）使用。
任何一处单独算一遍，都会出现"线没接在柱子上"。基向量表（`right/up/normal`）也只此一份。

#### 6.9.2 拉线手势（已实现）

| 步骤 | 操作 | 结果 |
|---|---|---|
| 1 | **右键**装好的端子 | **拿起线头**，提示"右键另一个端子完成连接" |
| 2 | **右键**另一个端子（任一手持线缆即可） | 服务端校验通过后**成线**，消耗 1 个线缆物品 |
| — | 再次右键**同一个**端子 | **取消**拉线 |
| — | Shift+右键端子（**空手**） | 拆端子（原有行为），**连着的线一起掉** |
| — | Shift+右键端子（**手持线缆**） | 仍然是**接线**，不是拆 |
| — | 挖掉/完整取下端子座 | 座上所有线**一起掉** |

- **客户端只管"线头"，服务端只管"成不成"**：线头是纯客户端状态，服务端**不记**
  待连接端；每次请求都把两端一起发过去，服务端从世界重新校验
  （两端都是端子座、格子里真有端子、这条线还不存在）。
  这样改包最多得到一个"玩家本来也能拉出来"的线，**不能穿墙、不能连不存在的端子**。
- **线缆规格由手持物品决定**：服务端读玩家手上的线缆，决定这条线是几安、什么绝缘，
  并只从**手上那一叠**扣 1 个。手上没有线缆就**不能成线**（"接线必须手持线缆"）。
- **"手持线缆"看的是两只手，不是进行这次交互的那只手**：把线盘放在副手、空手右键，
  是玩家很自然的拿法。只看主手会把它读成"移动线头"，点击像没反应一样。
  客户端与服务端都走 `PendingCable#heldCable`（主手 → 副手），判定必须一致。
- **拿端子不会拉线**：右键端子只在手持线缆时才是"接线"，否则只是"拿起/移动线头"，
  且不成线。这是为了避免玩家想装端子却意外拉出一条线。
- **潜行不改变接线语义**：手持线缆时，Shift+右键端子**照常接线**。
  早期版本先判 Shift，导致"蹲着点端子"要么没反应、要么（副手持线时）把端子拆了。
- **距离：分两种，不是"两端都得伸手可及"**：
  - **刚点的这一端**必须在常规交互距离内（眼睛到方块中心，额外 +1 格容差吸收发包延迟）——
    这是服务端能信任的那一次点击；
  - **另一端**允许在房间里任意远处，但**单根线缆最长 64 格**（`MAX_CABLE_SPAN`）。
    超了会提示"两端相距超过 N 格"。
  - 早期版本要求**两端**都在 4.5 格内，于是所有比手臂长、又不够站在中间同时够到两端的线缆
    **永远连不上**：短线能成、长线必败，表现为"有概率连不上"。
- **失败一定有提示**，不再静默：`stale`（点击已过期）/ `too_far`（超 64 格）/
  `rejected`（端子没了，或这条线已经拉好）/ `need_cable`（手上没有线缆）。
  重复拉同一对端子的同规格线缆**不会**再白扣线缆物品。

- **端子接线数量不限**：一个端子可以接任意多根线。要分线不必另找端子，
  现实中一个接线柱上并几根线也是常态。

#### 6.9.3 线缆怎么画（已实现）

**线缆是实体管，不是线段。** 早期版本用 `RenderType.lines()` 画四条平行细线冒充管子，
结果看起来像**一团细线**而不是一根粗线。原因在 GL 线图元本身：

- 线段**没有粗细模型**。`lines()` 向驱动要一条"粗线"，而粗线是把线段在**屏幕空间**拉伸出来的，
  于是每段都是一个断开的细长矩形，拐角处断开；
- 粗细取决于**驱动与窗口分辨率**，不取决于线缆；
- 4 条平行线并排，视觉上就是 4 根细线。

现在改为**沿悬链曲线扫掠出的实心棱柱**（**12 面**、两端封盖），用实体渲染管线
（`RenderType.entitySolid` + `POSITION_COLOR_TEX_OVERLAY_LIGHT` 顶点格式、QUADS、不透明、受光照）绘制：

- **粗细是真实几何**（单位：格），50 A 与 5000 A 在任何距离、任何分辨率下比例一致；
- 表面**参与遮挡与光照**，和端子一样是实体；
- 整根线共用**一个垂直标架**，否则每段各用一个标架会让管体在每个接点扭曲、在下坠段收腰。

**半径档位**：按**电流**而不是枚举序号计算，且用**四次方根**压缩。

```
直径(格) = 0.05 × (I / 50)^(1/4)          半径 = 直径 / 2
```

| 档位 | 载流量 | 直径（格） | 现实线径参照 |
|---|---|---|---|
| 铜 | 50 A | **0.050** | ≈ 5 mm |
| 铜 | 150 A | 0.066 | |
| 铜 | 500 A | 0.089 | ≈ 16 mm |
| 铜 | 1500 A | 0.117 | |
| 铜 | 5000 A | **0.158** | ≈ 50 mm |
| ACSR | 800 A | 0.100 | |
| ACSR | 1600 A | 0.119 | |

- **为什么用四次方根而不是立方根**：立方根版本把 5000 A 画到 **0.232 格**，
  在游戏里是一根**管子**而不是一根线。四次方根**不动 50 A 的下限**，只压缩顶端，
  正好是唯一看着不对的那一头。
- **为什么锚定在 0.05 格**：现实线径（0.005–0.05 格）直接画出来不到一个像素，必须放大；
  但**放大倍率随尺寸递减**，否则细档消失、粗档变管。0.05 格在 5–10 格外仍清晰可辨。
- **为什么不用枚举序号**：一旦插入一个"为别的理由存在"的档位（例如 800 A 钢芯铝绞线），
  按序号分布会让它画得**比 500 A 铜线还细**，而玩家读粗细读的是"能走多大电流"。

**颜色**取自线缆记录，经 `CableColor#renderedColor` 求值：
未上色时绝缘线为**灰外皮 `#8C8C8C`**、裸铜为**铜色 `#B87333`**、钢芯铝绞线为**铝色 `#B8BEC4`**；
染色后照常显示染料色（裸线不参与，§6.8）。

**下坠按材料**：铜 ×1.0，钢芯铝绞线 ×0.35。渲染与拾取**共用同一个系数**
（`TerminalGeometry.pointOnCable(..., sagMultiplier)` 与 `isNearCable(..., sagMultiplier)`），
否则钢芯铝绞线会因为画得直、却按铜的曲线判定而"点不中"。

**下坠幅度（已压缩，全部为视觉量）**：

| 参数 | 值 | 含义 |
|---|---|---|
| `SAG_RATIO` | **0.06** | 满跨距时中点下垂 = 跨距 × 6 %（再乘材料系数） |
| `MAX_SAG` | **1.0** 格 | 下垂上限：再长的线也最多垂 1 格，避免长跨距垂到地面 |
| `SHORT_SPAN_THRESHOLD` | **3.0** 格 | 短跨距阈值 |
| `shortSpanFactor()` | smoothstep | 跨距 < 3 格时按平滑曲线把下垂压到接近 0 |
| 跨距 < 1 格 | — | **直接拉直**，不做曲线（两个挨着的端子之间不该有一点弧） |

**分段是动态的**：`TerminalGeometry.sagSegmentsFor(from, to)`——
跨距 < 1 格取 2 段，否则 `clamp(ceil(跨距 × 2), 4, 64)`。
渲染与拾取**共用同一个分段数**，否则画出来的管子和判定用的折线不是同一条曲线，
表现为"看着点中了却没反应"。

**贴图：线缆不是一根纯色管子（已实现）**

现实中的线缆有内容——裸线能看到**绞合线股的螺旋**，绝缘外皮上有**喷码/标识**。
纯色圆柱看起来像塑料管，所以管体带 UV 贴图。

| 项 | 规格 |
|---|---|
| 位置 | `assets/stardustindustry/textures/block/cable_<variant>.png` |
| 变体 | `cable_bare`（裸铜）、`cable_acsr`（钢芯铝绞线）、`cable_class_1`（一类绝缘）、`cable_class_2`（二类绝缘） |
| 占位尺寸 | **32 × 128**（宽 × 高） |
| 颜色 | **灰阶 / 白色**，颜色由顶点色乘上去 |
| 横向 `u` | `0..1` = **绕截面一整圈**（12 个面等分，每面 1/12） |
| 纵向 `v` | 沿**曲线长度**推进，**每 2 格**重复一次（`TEXTURE_REPEAT_BLOCKS`） |
| 渲染管线 | 原版 `RenderType.entitySolid`（受光照、剔除、不透明），按纹理缓存 |

- **必须画成灰阶**：颜色来自线缆数据（默认灰外皮 / 铜色 / 铝色，或玩家染的颜色），
  贴图只负责**明暗与图案**。这样一张贴图就能服务所有颜色和所有电流档。
- **纵向按世界长度而非分段号**：长跨距和短跨距用同一套印刷尺度，线不会被拉长变形。
- **横向一圈**：标准圆柱贴图。因为管子很细（0.05–0.158 格），一圈 32 px 会被横向压缩，
  图案请以**纵向条纹 / 斜向绞纹 / 周期性色带**为主；细小文字在这个尺寸下看不清。
- **光照取的是端子座所在格的光照**，逐顶点采样会让细线在跨格处闪烁，所以整根线用同一个值。

**物品图标按规格独立绘制（已实现）**

17 个线缆物品各自使用一张 **16×16 全彩图标**：
`textures/item/cable_<amps>a_<insulation>.png`。图标直接编码导体粗细、绝缘等级标记和
自然材质色；物品模型不再声明 `tintindex`，客户端也不注册额外的物品颜色处理器。

- **物品图标与世界管体分开着色**：世界线缆仍使用灰阶管体贴图乘顶点色，物品图标则直接
  使用 PNG 里的最终颜色。两者不能叠加，否则绝缘图标会被自然灰再次相乘而变得接近黑色。
- **一规格一图标**：背包中的轮廓和刻线需要表达载流量与绝缘等级，不能只靠四张共用图。
  旧的 `cable_{bare,acsr,class_1,class_2}.png` 仅保留给下游资源包兼容，当前物品模型不引用。
- **与 §6.8 不冲突**：物品显示产品的自然材质色；玩家染色仍只写在铺设后的线缆记录里，
  裸线不可染色的规则不变。

### 6.10 过载：冒烟，然后是 TNT

**唯一的故障是过载。** 导线被电流烧坏只有一个原因：**流过的电流超过它的载流量**。
电压高不会烧线——那是 §6.11 的触电问题，是玩家的事，不是线的事。

**载流量的有效值**：

```
I_max(有效) = ampacity × 绝缘系数
             = 50/150/500/1500/5000 A × (100% / 90% / 80%)
```

**超载比例决定寿命**（按现实时间比例缩放，不是 tick 数堆叠）：

| 超载倍数 | 从开始冒烟到失效 |
|---|---|
| 1.2 倍 | ≈ 60 秒 |
| 2 倍 | ≈ 15 秒 |
| 5 倍以上 | 几秒 |

**冒烟是过程，不是终点。** 玩家还有机会处理：

| 阶段 | 表现 |
|---|---|
| 刚超载 | **白色粒子**，稀疏 |
| 持续超载 | 粒子**变深、变密**（灰 → 深灰） |
| 临近失效 | **黑色粒子**，浓密 |
| 降负荷 | 粒子**逐渐变淡**并消失（不是立刻归零，给玩家"已经快好了"的反馈） |

**失效后果按电流档分两种**：

| 电流档 | 后果 |
|---|---|
| **50 A** | 线缆**直接断开消失**（细线烧断，不值一炸） |
| **150 A 及以上** | 在**这条线的所有线路端口**各产生 **1 个 TNT 威力爆炸**，**不破坏方块**，随后线缆消失 |

- 任何会爆炸的过流失效都必须先连续确认至少 **40 tick**。热量与连续确认分别记录：
  任一 tick 低于过载阈值都会把 40 tick 计数清零，但既有热量仍按 30 秒曲线逐步冷却。
  因此预热电缆也不能被一次短脉冲立即引爆。
- **为什么 150 A 以上是爆炸而不是烧断**：粗导体烧断时储存的能量大，
  现实里粗电缆故障是会炸的；游戏里也让"用细线冒充粗线"变成**有代价**的决策。
- **为什么不破坏方块**：玩家精心搭的机器不该因为一次计算失误被炸掉。
  爆炸只伤害**生物**（包括玩家），推挤和音效照常，破坏力留给战斗而不是建筑。
- **为什么爆炸出现在所有端口**：故障的能量沿线路传导，两端、以及每个接线的端子都会打火。
  这也让"一根线串太多设备"有风险。

- 当前按上表执行热累积与失效；可切换的过流软限制属于 §8.6 的后续配置规划。

### 6.11 触电：绝缘只保玩家的命

**绝缘不决定"能不能接"，只决定"碰了会不会死"。**

线缆可以接任何电压的端子，接了就是接了，绝缘**不会**因为电压太高而炸毁——
如果那样，"用了不够好的线"这件事就会变成一个玩家看不懂的爆炸。
让它变成**一件会电死人的事**，规则反而清楚：**你碰了它，你就知道它不够好。**

**绝缘档位只有 3 种**（其中一种是"没有绝缘"）：

| 绝缘 | LV（380 V） | MV（10 kV） | HV（110 kV）及以上 |
|---|---|---|---|
| **裸线** | 轻伤 | **必死** | **必死** |
| **一类绝缘** | 无伤 | **轻伤** | **必死** |
| **二类绝缘** | 无伤 | 无伤 | **必死** |

- **再往上没有更高档**：HV 和 EHV 只能靠"别碰"来保护，这也是现实的样子——
  110 kV 以上的东西不存在"绝缘手套"这种解法。
- **触碰判定**：玩家身体碰到线缆的碰撞体，或站在带电线路下方时，按**当时线路的电压**
  查上表。
- **伤害**：
  - 轻伤：若干点伤害 + 一次击退与音效，**不会死**；
  - 必死：**生命值直接清零**，不看护甲、不看抗性。
- COMMON 配置提供总开关、轻伤伤害与致命伤害；轻伤始终至少保留 1 点生命，致命伤害
  使用绕过普通防护的伤害类型。
- 这条规则让"高压线"成为**必须规划走线、远离玩家活动区**的真实危险，
  也是"为什么高压要架高、要隔离"的直接体现。
- **裸线可以修好**：给裸线套上绝缘（或者换成有绝缘的线）就安全了，
  不需要拆掉重铺——这是玩家从这次触电里学到的**补救手段**。

### 6.12 规格阶梯

> 数值为**建议初值**。线缆**不分电压等级**，只有**材料 × 载流量 × 绝缘**三个维度。

**铜导体（5 档，每档约 3 倍）**：

| 档位 | 载流量 | 电阻/格 | 典型用途 |
|---|---|---|---|
| **50 A** | 50 A | 8.00×10⁻⁵ Ω | 照明、控制回路、小机器 |
| **150 A** | 150 A | 2.67×10⁻⁵ Ω | 车间馈线 |
| **500 A** | 500 A | 8.00×10⁻⁶ Ω | 工厂 LV 母干线、MV 配电 |
| **1500 A** | 1500 A | 2.67×10⁻⁶ Ω | MV / HV 变电站馈线 |
| **5000 A** | 5000 A | 8.89×10⁻⁷ Ω | HV / EHV 主干输电 |

**钢芯铝绞线（2 档，只有裸线）**：

| 档位 | 载流量 | 电阻/格 | 下坠 | 典型用途 |
|---|---|---|---|---|
| **800 A** | 800 A | ~1.62×10⁻⁵ Ω | ×0.35 | MV 架空长跨距 |
| **1600 A** | 1600 A | ~5.39×10⁻⁶ Ω | ×0.35 | HV 架空长跨距 |

> 钢芯铝绞线的电阻按**同等电流**的铜基准 × 1.3 计算。它的电阻**始终比同载流量的铜高**，
> 这是它换取"轻、能架远"所付的代价。

**绝缘 3 档**：裸线 / 一类 / 二类，载流量系数分别 **100 % / 90 % / 80 %**（§6.10）。

**物品总数**：铜 5 × 3 = 15，钢芯铝绞线 2 × 1 = 2，共 **17 种**。
命名 `cable_<载流量>a_<绝缘>`，例如 `cable_500a_class_2`、`cable_1600a_bare`。

- **距离是真实成本**：`R = R_perBlock × 格数`（格数按 §6.9 四舍五入），线损随格数线性上升。
- **载流量与导体根数是两套数**：前者来自 `CableAmpacity` 的真实安培值；后者来自
  `WiringMode.requiredConductors()`（2 / 3 / 4 根），只描述端口接线制。两者不要混用。
- 高等级线缆**有物理占位要求**（高压架空线需要间隔、需要绝缘子）——**本轮不做**（§13），
  只作为目标设计保留。

## 7. 变压器

### 7.1 基本行为

- 两端各属一个电网；**输入侧按它所属电网的电压运行，输出侧按另一电压运行**。
- **功率守恒（近似）**：`P_out = P_in × η_transformer`（当前固定 η = 0.98）。
- 电流按各侧接线公式从功率反算：单相 `I=P/U_phase`，平衡三相
  `I=P/(√3·U_line)`；两侧同为三相时 `√3` 在功率守恒关系中抵消。

### 7.2 变比与档位（建议）

- 变压器支持**相邻等级**互转（如 MV↔HV），不建议一级跨到任意等级。
- 可选：升级器件后支持指定变比（如 110 kV → 10 kV 的变电站）。

### 7.3 为什么必须有变压器（设计校验）

如果去掉变压器，玩家只能"用多大电压，就用多大电压送到多远"——
**低功率近距离**没问题，**高功率远距离**必然被线损吃掉。变压器的存在让
"在电源处升压 → 远方降压"成为唯一解。**这是本系统区别于所有 FE 模组的核心。
必须在教程/手册里明确讲清这条因果链。**

## 8. 机器：额定电压、保护与爆炸

### 8.1 额定电压

- 每台静态机器的额定**电压**由机器模板声明；底座/框架方块不再决定电压。
- **机器只声明电压等级**（工业设备以 380 V 为主）；单相/三相是**导线与接口的接线属性**（§4.2）。
- 机器只接受等于额定电压的电网。

### 8.2 三类故障

设备层面对三类故障，**是否损坏取决于有没有外置保护**：

| 故障 | 触发条件 | 有保护 | 无保护 |
|---|---|---|---|
| **过压** | 接入高于额定电压的电网 | 保护动作，跳闸/隔离 | 连续确认 40 tick 后**端口爆炸**（§8.3、§8.4） |
| **过载** | 通过机器的电流/功率超额定 | 保护动作，限流/跳闸 | 过热损坏 / 爆炸 |
| **缺项**（缺相） | 部分所需导体由闭合电源带电，但三相未接全 | 保护动作，停机 | 连续确认 40 tick 后**爆炸**（威力见 §8.4） |

- **欠压**（接入低于额定电压）不属于故障：**无反应 + 提示，不损坏**，接对即恢复。
- **统一确认窗口**：所有可能爆炸的路径都必须连续成立至少 **40 tick**；任一 tick 恢复正常、
  断电或端口离线都会重置确认。未通电的半成品接线不属于带电缺相，也不会爆炸。
- **机器本身不带任何保护**。保护**全部来自外置设备**（断路器/保险丝/继电器等，
  见 §9.3）——玩家必须自己为线路和机器配保护。这正是"该不该花钱装保护"的真实决策。
- **保护**是独立的可安装部件（外置，§9.3）；机器无论哪个等级**都不内建保护**。

### 8.3 过压：只炸端口

- **没有保护时，高压进低压设备持续 40 tick → 爆炸。**
- **只炸端口**，不是炸整台机器：损坏的是那个接线端口方块（可单独更换/修理）。
- 变压器、FE 转换器等单方块设备的输入端与设备块合为一体；它们没有可拆分端口，
  因此未受保护的输入故障会在同样的 40 tick 确认后损坏该设备块。
- 这样损坏**局部、可修复**，既严重又不至于让玩家重建整个多方块。
- 威力取决于**等级差**，见 §8.4。

### 8.4 爆炸威力（统一公式）

**规则**：

- 下列威力只在故障连续确认至少 **40 tick** 后生效，不存在瞬时爆炸路径。
- 基准：**高一级接低一级 = 2 个 TNT**。
- 每再高一级，威力 **×3**。
- 等级差 `Δ`（接入电压等级 − 设备额定等级，`Δ ≥ 1`）时：

```
威力(TNT) = 2 × 3^(Δ−1)
```

| 等级差 Δ | 例子 | 威力（TNT） |
|---|---|---|
| 1 | 10 kV 接 380 V 设备 | 2 |
| 2 | 110 kV 接 380 V 设备 | 6 |
| 3 | 500 kV 接 380 V 设备 | **18** |

- **默认不破坏地形**：爆炸只有伤害与范围，不挖方块（避免玩家被"炸掉家"）。
- 当前固定为不破坏地形；是否允许地形破坏属于 §8.6 的后续配置规划。
- 单级威力（基准 2）与每级乘数（×3）当前为代码固定值。
- **缺项爆炸**：固定 **2 个 TNT**（不随等级差放大——缺项是"相数不对"，不是"电压不对"），
  同样只炸端口；单独配置威力属于 §8.6 的后续规划。

### 8.5 待机耗电（沿用并强化）

现有设计：等级越高，待机耗电越大（`chargeIdleDraw()` 按 tier 电压扣电）。
在新模型下，这仍然是"高等级 ≠ 无脑更好"的平衡点，保留。

### 8.6 电气配置项

触电配置已经接入 COMMON 配置。爆炸与保护参数仍使用代码固定行为；表中标为“规划”的
键不能当作现版本已经可用的配置键。

| 规划配置键 | 规划默认 | 说明 |
|---|---|---|
| `explosion.basePower` | 2.0 | 高一级接低一级的 TNT 威力 |
| `explosion.powerStep` | 3.0 | 每再高一级的威力乘数 |
| `explosion.missingPhasePower` | 2.0 | 缺项爆炸威力（TNT） |
| `explosion.destroysTerrain` | false | **是否破坏地形**（默认关） |
| `explosion.overcurrentSoftLimit` | true | 过流是否软限制（默认是；关则熔断爆炸） |
| `explosion.protectionEnabled` | true | 是否允许保护部件生效 |
| `electricShocksEnabled` | true | 绝缘不足的带电线缆是否电击玩家（已实现） |
| `lightShockDamage` | 4.0 | 轻伤伤害点数；不会扣除最后 1 点生命（已实现） |
| `lethalShockDamage` | 1000.0 | 致命触电伤害点数，使用绕过普通防护的伤害类型（已实现） |

> ⚠️ **未来实现时必须写进配置文件注释与手册的性能提醒**：开启 `explosion.destroysTerrain`
> 后，高等级差爆炸会**在瞬间破坏大量方块**，触发****大规模方块更新、光照重算、
> 区块重发与掉落物/音效开销**，在低端机或大型电网连锁故障时可能造成**明显卡顿甚至崩溃**。
> 该选项默认关闭；仅在明确知道后果时开启，并建议配合"保护部件"降低连锁爆炸概率。

## 9. 发电机与储能

### 9.1 发电机

- 发电机有**额定输出电压**与**额定功率**。
- 输出功率可受"燃料/蒸汽/转速"调节；电压固定（或经内部变压器）。
- 与电网的电压一致性规则同 §5.2：发电机电压必须与所接电网匹配。

### 9.2 储能（电池/电容）

- 内部结算与存档统一存**能量（J）**，不是功率。
- 面向玩家的物品提示、状态消息与界面不直接显示巨大焦耳数，而是按量级自动使用
  **kWh / MWh / GWh**。
- 充放电受**最大功率**限制（进 = `U·I_charge_max`）。
- 储能可充当电网的"源"（放电时）。
- **不同电压的储能不能直连**，必须经变压器。

### 9.3 保护部件

设备层的三类故障（§8.2）由**可安装的保护部件**应对：

| 部件 | 应对故障 | 行为 |
|---|---|---|
| 断路器 / 空气开关 | 过压、过载、缺项 | 越限即跳闸，隔离故障段，可手动复位 |
| 保险丝 | 过载 | 越限即熔断，需更换（一次性） |
| 继电器 / 保护器 | 过压、缺项 | 监测并触发跳闸/告警 |

- 保护**按段部署**：一条线上的保护只保护其下游，故障被限制在最小范围。
- **有保护 → 跳闸，无保护 → 爆炸**（§8.2）。这是"该不该花钱装保护"的真实决策。

## 10. 与 FE 及外部模组的关系

### 10.1 定位：**自有系统为主，FE 仅作跨模组适配**（已定）

- **模组内部**：完整的 `U/I/P/R` + 线损，走自有电网。
- **对外**：普通设备不暴露 NeoForge `IEnergyStorage`，避免 FE 绕过电压、导体和保护规则。
- **桥接**：只有专用 **FE ↔ 电** 转换器暴露 FE capability：
  - FE → 电：`P = FE/t × 换算`，作为电网的一个"源"；
  - 电 → FE：反向，按功率结算并施加转换损耗。
- **损耗**：双向固定效率 95%，既符合物理，
  也避免"用本模组的高压线无损地给 FE 机器灌电"变成无脑最优解。

### 10.2 单位换算锚点

固定 `1 FE = 1 J`（见 §3.1）。20 tick = 1 秒，因此连续 `X FE/t` 对应 `20X W`；
转换器按每 tick 的实际能量结算，并施加 5% 损耗。

## 11. 现实细节清单（哪些做、哪些不做）

| 现实概念 | 决定 | 理由 |
|---|---|---|
| 电压 / 电流 / 功率 | ✅ 全做 | 系统核心 |
| 线损 `I²R` | ✅ 做 | 让高压与变压器有意义 |
| 电压降 | ⚠️ 部分 | 计算 `U_drop=I·R` 以求焦耳损耗，但不向下游传播端点电压 |
| 集肤效应 | ❌ 不做 | 只影响交流细节 |
| 功率因数 / 无功 | ❌ 不做（可作附属） | 理解成本极高 |
| 频率 / 并网同步 | ❌ 不做 | v1 只求解标称电压下的有功功率与线路损耗 |
| 三相建模 | ✅ 平衡模型 | `P=√3·U_line·I`、三相总损耗 `3I²R`；不建模相序、相角或无功（§6.5） |
| 端子 / 多导体 | ✅ 做 | 软线核心；端子座网格 + 单个端子（§6.3、§6.4） |
| 多芯线缆 + 专用节点 | ❌ 后续 | 一根走多芯；节点只直通不分路（§6.6） |
| 线槽 | ❌ 后续 | 一格 32 根、连接材质、开口朝上；进槽长度三段相加（§6.7） |
| 线缆上色 | ✅ 做 | 区分线路、防线槽内/密集布线混淆（§6.8） |
| 悬链线下坠 | ✅ 做（仅视觉） | 电气长度按格四舍五入（§6.9） |
| 触电（绝缘与电压矩阵） | ✅ 做 | 服务端按真实带电快照与线缆几何判定（§6.11） |
| 变压器 | ✅ 做 | 系统灵魂 |
| 绝缘击穿 | ❌ 不做 | 绝缘只影响触电安全与载流量降额，不造成爆炸（§6.10、§6.11） |
| 过载爆炸 | ✅ 做 | 导线两大限制之二（§6.10） |
| 过压爆炸（只炸端口） | ✅ 做 | 最有教育性（§8.3、§8.4） |
| 缺项保护 | ✅ 做 | 三相设备的真实故障（§8.2） |
| 断路器 / 保险丝 / 继电器 | ⚠️ 部分 | 断路器与保险丝已实现；继电器后续（§9.3） |
| 地形破坏 | ❌ 当前不做 | 爆炸固定不破坏地形；可配置开关仍是规划（§8.6） |
| 环网潮流求解 | ❌ 本轮不做 | 性能与复杂度 |

## 12. 对现有实现的影响与迁移

### 12.1 当前实现

- `energy/EnergyTier`：只保留物理电压与独立的流体吞吐量，不再保存 FE 功率档。
- `energy/WiringMode`：单相二线、三相三线、三相四线；接线方式决定所需导体数、
  标称电压、缺相判定与电流换算。单相按 `P/U_phase`，平衡三相按
  `P/(√3·U_line)`；四线制中性线在正常平衡状态下电流为 0。
- `energy/ElectricalGridService`：按导体 DSU 构图，求解活动电网、线损、储能充放电与过流热量。
- `energy/ElectricalUnits` / `energy/RadialCableFlow`：每段先按欧姆定律计算
  `U_drop=I·R`，再按 `P_loss=I·U_drop` 累计焦耳损耗；端口仍使用线路标称电压，
  不传播逐节点电压降。
- 早期 `machine/TerminalBlock` 整体端子方案已经移除；当前按 §6.3 使用
  `TerminalMountBlock` + 单个端子，由方块实体记录格子占用。
- `machine/module/JouleStorageModule`：使用 `long` 焦耳，旧 `Energy` 字段按 1:1 迁移。
- `registry/ModCapabilities`：普通端口只暴露原生 `IElectricalPort`；仅 FE 转换器暴露 FE。
- `recipe/ProcessingRecipe`：使用 `power_watts`；旧 `energy_cost` 临时按 `×20 W` 兼容并告警。
- 储能内部仍以 J 结算；面向玩家按量级自动显示 kWh/MWh/GWh。
- `multiblock-design.md` §4.5：**底座等级 = 电压档**已作废，改为静态机器额定电压写死模板（§4.5.1）。

### 12.2 迁移要点与延期边界

1. **`EnergyTier` 增加/改名字段**：把现有 `voltage`（其实是功率档）与真正的
   "标称电压 `volts`"分开。建议：
   - `volts`：物理线电压（380 / 10000 / 110000 / 500000）；
   - 旧的 `voltage` 语义改为 `powerClass` 或直接由 `volts × amps` 表达，
     避免"电压=功率"的混淆长期留在代码里。
2. **`maxAmperage` 提升为真载流量**：与导线 `I_max` 同一量纲；单相额定功率为
   `U_phase·I_max`，平衡三相额定功率为 `√3·U_line·I_max`。
3. **接线属性**：**端子/导线**承载 `conductors`（导体根数）与 `phase`（单相/三相，
   仅作接线提示，不建模相序）；**静态机器不再有"底座等级"，额定电压写死在机器模板**
   （`multiblock-design.md` §4.5.1）（§4.2、§6.4、§6.5）。
4. **端子座（`TerminalMountBlock`）+ 端子（`TerminalPinItem`）**：软线的连接节点与电网节点。
   **端子座**是一个方块，提供规则网格（**LV 4×4 / MV 2×2 / HV、EHV 1×1**）与朝向；
   **端子**是装在格子里的独立端位/节点，用方块实体记录占用集合（不用方块状态枚举，16 格不可行）。
   镐挖散开掉底座+端子；安装工具 Shift+右键完整取下（§6.3）。
5. **后续（未实现）· 多芯线缆 + 专用节点**：一根线缆多芯；专用节点**只固定、只直通，不分路**
   （分路走端子/配电箱）（§6.6）。
6. **后续（未实现）· 线槽（`CableTrayBlock`）**：一格、连接材质、开口朝上、**最多 32 根**、可贴墙；
   入口/出口连接流程见 §6.7；**进槽线缆长度按三段相加**（端子→入口 + 入口→出口 +
   出口→端子，各自取整）。
7. **导线**：新增**柔性导线**（`CableBlock` / 端子间连线，含
   `I_max` / `R_perBlock` / `insulation`）与电网 DSU；实现 §6.10 过流、
   §6.4 多导体（根数/缺项）与 §6.9 悬链线视觉。绝缘不击穿，只参与载流量降额；
   §6.11 触电已按实时带电电压、绝缘等级与共享悬垂几何实现。线缆带**颜色**数据
   （**合成时上色**，纯标识、不影响电气，§6.8）。（**硬质铜排暂缓**。）
8. **变压器**：通过 `ElectricalDeviceBlock` 的变压器类型实现双电压端、变比与损耗。
9. **端口**：`*_energy_port` 保留，语义改为"电网接线点"，接上后在 DSU 里注册。
10. **机器额定电压校验**：`MachineBlockEntity` 侧在接入电网时校验 `volts`（来自模板），
    实现过压爆炸（只炸端口，§8.3/§8.4）、欠压无反应 + 提示；缺项由端子的
    `conductors` 判定（§4.3、§6.4）。
11. **保护部件**：已新增断路器与保险丝（**外置**，§9.3），实现按下游段传播的
    "有对应保护→跳闸，无对应保护→爆炸"。继电器仍属后续；机器不内建保护。
12. **爆炸 / 触电与配置**：§8.4 威力公式 `2 × 3^(Δ−1)` 与 40 tick 故障确认已落地；
    爆炸固定不破坏地形。§6.11 触电和对应 COMMON 配置已落地，爆炸配置仍属后续。
13. **参数屏**：新增"额定电压 / 当前电流 / 线损 / 效率 / 保护状态"等行
    （沿用 `MachineParamsData` 机制，**专属数值放进机器自己的快照块，不复用通用字段**
    ——见 `multiblock-design.md` §4.6.1 约定）。**界面显示电压即可**（§4.4）。
14. **文档同步**：`multiblock-design.md` §4.5 的等级表、`EnergyTier` 的 javadoc、
    `docs/README.md` 索引、`CHANGELOG.md`。

> **已定（本轮批复）**：
> - §4 电压阶梯与"单相/三相为接线属性"（方案 1）；**等级与电压一起显示**（§4.4）。
> - **单相 + 平衡三相求解**：单相使用 `P=U_phase·I`，三相使用
>   `P=√3·U_line·I`，三相总线损为三根相线的 `I²R` 之和；功率因数固定为 1，

> - 过压连续 40 tick = 只炸端口；威力 `2 × 3^(Δ−1)`；当前固定不破坏地形（§8）。
> - **机器无保护，保护全部外置**（§8.2、§9.3）。
> - **端子 = 端子座 + 端子**：端子座给规则网格（**LV 4×4=16 / MV 2×2=4 / HV、EHV 1×1=1**），

>   安装工具 Shift+右键完整取下（§6.3）。
> - **多导体**：一组线路由多根独立导线组成；端子可在放射状网络中分线，但拒绝同端点重复线、
