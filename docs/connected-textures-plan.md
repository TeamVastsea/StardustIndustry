# 连接材质（Connected Textures）方案与美术资源需求

> **当前状态（重要）**：连接材质**已从主模组中剥离**，暂缓实现。主模组内所有方块
> （含储罐框架/外壳/玻璃）**一律使用普通 cube 模型与默认贴图**，不再使用 connected
> texture / 连接覆盖模型。
>
> 将来若确认有必要，**另开一个附属模组（add-on）**单独实现连接材质。届时直接复用本文
> 的方案、贴图清单与命名规则即可，无需重新设计。本文因此同时作为**策划案**与**美术案**
> 的输入：策划侧说明「为什么/什么时候做」，美术侧说明「要出哪些图」。
>
> 主模组内**唯一保留**的相关行为是 `TankGlassBlock.skipRendering`：相邻同类玻璃之间跳过
> 重合面，避免半透明叠加出的缝合亮线。这属于**修渲染瑕疵**，不是连接材质，故保留。

> 目标：让储罐的**框架、外壳、玻璃**在彼此相邻时自动「连成一片」，
> 消除方块之间重复的接缝线，让 3×3×3 甚至更大的储罐看起来是一个整体容器，
> 而不是一堆小方块拼起来。
>
> 状态：**暂缓（由附属模组实现）**。本文件是给美术的方案说明 + 出图清单。
>
> 最后更新：0.1.0

---

## 一、先说清楚「连接材质」在本项目里指什么

我们说的「连接材质」是这类效果：

- 两块相邻的同类方块之间，**不再画出各自的边线**，看起来是一整块连续的表面；
- 只有**暴露在最外侧**的边才画线（就是容器真正的外轮廓）。

这在 Minecraft 里有两大类实现方式：

| 类别 | 原理 | 是否需要特殊贴图 | 是否需要装模组 |
| --- | --- | --- | --- |
| **A. 原生 multipart（几何法）** | 用方块状态记录「哪几个面与邻居相连」，blockstate 里用 multipart 叠加不同的模型/贴图 | 需要**多张定向贴图** | **不需要**，原版就能跑 |
| **B. 连接材质模组（CTM）** | 贴图层面自动拼接，一张大图 + 规则文件 | 需要**图集专用贴图**（如 4×4 拼块） | **需要**装 CTM 模组 |

本项目**已经有一套 A 类设施**：端口方块（`lv_item_port` 等）已经用
`multipart` + 6 个 `*_conn_<方向>.json` 模型来做「哪面连着就画哪面」。
所以对储罐框架/外壳/玻璃做连接材质，技术上**顺着已有模式扩展即可，不需要引入新模组**。

下面给出四条可选路线，从「最简单、零依赖」到「效果最完整、但要装模组」。

## 二、四条候选方案

### 方案 A：原生 multipart 连接（**推荐**）

**怎么做**：给 `tank_frame` / `tank_shell` / `tank_glass` 各加 6 个布尔方块状态
（`north/east/south/west/up/down`），在方块类里每次邻居变化时更新；
blockstate 用 `multipart` 叠加「连接面」模型，把内部接缝「补平」或「去掉边线」。

**美术需要出什么**：需要一套**去边框的中心贴图** + **带边框的边缘贴图**的分面素材。

- 优点：**零模组依赖**，玩家不装任何东西也能用；和现有端口系统一致；行为完全可控。
- 缺点：连接只在**同种方块**之间成立（框架连框架、外壳连外壳），
  框架和外壳相交处需要专门规则；6 个状态 = 最多 2^6 种组合，需要细心建模但可控。
- 工作量：程序中等，美术中等。

**这是我们建议的主方案**，因为它不牺牲兼容性——一个工业模组不该要求玩家
为了看对贴图而额外装连接材质库。

---

### 方案 B：原生 multipart 的「简化版」（**稳妥备选**）

**怎么做**：不追求 6 面全连，只处理**水平 4 方向**（东南西北）的连接，
顶/底永远画边框。对储罐这种「四壁 + 顶底」的结构，视觉收益已经占 80%。

- 优点：实现和出图都减半，不易出错。
- 缺点：顶面之间的接缝仍在；俯视时会看到格线。
- 适合：美术资源紧张、先出能看的版本。

---

### 方案 C：接入 CTM 模组（**效果最好，但强依赖**）

**怎么做**：支持 Fusion（原 ConnectedTexturesMod 的 1.21+ 继任者）
或 Athena 等 CTM 库，用它们的格式写 `.properties` / 图集。

**美术需要出什么**：一张**连接图集**（通常 4×4=16 格或 5×5=25 格拼块），
外加规则文件。

- 优点：真正的「任意方向、任意形状」自动连接，效果最接近现代工业模组。
- 缺点：**玩家必须装 CTM 模组**；不装就退回普通贴图；等于增加一条软依赖链。
- 适合：以后如果整个模组的美术都走 CTM 风格，再统一引入。

---

### 方案 D：方块模型层「真·大模型」（**不作为通用方案**）

**怎么做**：储罐成型后，不渲染每个小方块，而是用 `MachineRenderer` 直接画
一个覆盖整个结构的**外壳大模型**（类似我们的流体渲染器）。

- 优点：连接是「物理上」成立的，绝对无缝。
- 缺点：只对**已成型**的储罐有效；玩家搭建过程中仍是小方块；
  和「拆掉一块就散架」的表现要额外处理；等于绕开方块系统自己画世界。
- 适合：作为**成型后的额外美化**，和方案 A 叠加使用（成型后盖一层大模型外壳）。
- 现状：我们已经有了成型后渲染流体的先例（`TankLiquidRenderer`），
  要扩展成「成型后画外壳」不难，但优先级低于 A。

## 三、推荐组合（**已定案**）

| 结构类型 | 采用方案 | 说明 |
| --- | --- | --- |
| **动态多方块结构**（储罐等） | **方案 A 的「面板无边框」变体（方案甲）** | 面板贴图本身不画边框 → 相邻块天然无缝；整个结构轮廓由**框架**提供 |
| **固定结构的机械**（破碎机等） | **方案 D**：成型后画大模型外壳 | 由 `MachineRenderer` 在成型后渲染整机外壳，物理上无缝 |

> 已确定：分辨率统一 **16×16**；边框用**两套贴图**而非裁切；风格偏现代。

### 为什么选「面板无边框」而不是「逐面切边框」

真正的接缝出现在**你正看的那一面**上（例如 3×3 外壳墙朝北看，9 块的北面之间的竖线）。
「两套贴图（带边框 / 无边框）」只能**整面**切换：朝空气的面都是「带边框」，
所以同面内相邻两块之间的缝无法靠整面切换消除。要做到「外轮廓有边框 + 内部无缝」，
必须按**面的四条边分别**决定（九宫格裁切）——即被否定的裁切方案。

**方案甲**绕开了这个矛盾：**面板贴图完全不画边框**，相邻面板自然拼成一片；
储罐的外轮廓由**框架方块**（12 条棱，带边框）勾勒。这正是
IE 铁皮罐等工业模组的通行做法，且完全满足「不裁切 + 可用两套贴图」。

| 贴图 | 边框 | 说明 |
| --- | --- | --- |
| 框架 `<名称>.png` | **有**（外露的棱） | 勾勒结构轮廓 |
| 框架 `<名称>_inner.png` | 无（棱延续时） | 框架相接处不出现分界线 |
| 面板 `<名称>.png` | **无** | 相邻面板无缝 |
| 面板 `<名称>_inner.png` | 无 | 同上 |

## 四、方案 A 的程序侧设计（供实现参考，美术可跳过）

1. **方块状态**：给三个方块各加 `Property<Boolean> NORTH/EAST/SOUTH/WEST/UP/DOWN`，
   共 6 个。
2. **更新时机**：方块 `onPlace`、`neighborChanged`、`onRemove` 时重新计算
   6 个方向「邻居是否为同类或其允许的相连体」，写回状态。
3. **相连规则**（需要和美术/玩法确认）：
   - 框架 ↔ 框架：相连；
   - 外壳 ↔ 外壳：相连；
   - 玻璃 ↔ 玻璃：相连；
   - **外壳 ↔ 玻璃**：是否相连？（建议**不相连**：玻璃要露出外壳的边框才好看）
   - **框架 ↔ 外壳/玻璃**：建议**不相连**（框架是骨架，要始终露边）。
4. **模型组织**：复用现有 `*_conn_<方向>` 模式，每个方块一套：
   - `tank_frame`（中心/本体）
   - `tank_frame_conn_<方向>` × 6（连接补片）
   - 外壳、玻璃同理。
5. **面剔除优化**：相邻同类方块之间的内部面可以直接不渲染，省性能。

## 六、已定项与仍需美术商定项

### 已定（程序据此实现）

| 项 | 结论 |
| --- | --- |
| 分辨率 | **16×16** |
| 连接范围 | **6 面全连接** |
| 边框处理 | **两套贴图**（带边框 / `_inner` 无边框），**不做 UV 裁切** |
| 服务对象 | 连接材质**主要服务动态多方块结构**（储罐等） |
| 固定结构机械 | 走 **方案 D**（成型后大模型外壳） |
| 风格 | **由美术自行商定，整体偏现代** |
| 边框粗细 | **由美术自行商定** |

### 仍需美术商定（不影响程序开工，出图前定即可）

1. **相交规则**：外壳与玻璃相邻时**相连**（表面连续）还是**不相连**（露出玻璃边框）？
   框架与其它方块相邻时是否始终露边？
   —— 程序默认：框架↔框架、外壳↔外壳、玻璃↔玻璃**各自相连**；
   框架不与外壳/玻璃相连（保持骨架外露）；外壳与玻璃**不相连**（玻璃露边框）。
   若美术想改，只需改一处规则。
2. **风格参照**：有没有想对标的模组/材质包？（IE 钢板、Mekanism 机身、匠魂玻璃等）
3. **边框粗细**：16×16 下边框占几个像素？（1px 精致 / 2px 厚重）

## 八、一句话总结

- **动态结构走方案 A**：6 面全连接，用项目已有的 multipart 模式，**零模组依赖**。
- **固定结构机械走方案 D**：成型后由渲染器画整机外壳，物理无缝。
- **统一 16×16；边框用两套贴图（带边框 / `_inner` 无边框），不裁切。**
- **美术现在就能开工**：§五 的贴图，其中**储罐三件套（含 `_inner` 版）最优先**。
- 风格与边框粗细由美术商定，整体偏现代；唯一还需美术定的是 §六 的「相交规则」。
