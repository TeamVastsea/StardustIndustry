# OBJ 模型手册（美术用）

> **本文是 OBJ 类模型（端子、线缆接头、以及后续一切外挂模型）的唯一权威说明。**
> 贴图替换看 [`textures-placeholder-manual.md`](textures-placeholder-manual.md)，
> 本文只管**几何文件 + 摆放配置**。
>
> 最后更新：0.1.0 · 适用：NeoForge 1.21.1 / `neoforge:obj` 加载器

## 零、30 秒速记（只记这三条也能开工）

1. **原点 = 模型底部中心**，不是模型中心。`(0,0,0)` 就是端子"踩"在插座上的那只脚。
   （详见 §3.4，含判定方法）
2. **模型沿 `+z` 长出去**，所有顶点 `z ≥ 0`，`x` 和 `y` 关于 `0` 对称。
3. **尺寸由你决定，引擎不缩放**——画多大就是多大。
   但端子放在方块里的净深度别超过 `9/16` 格（562.5 mm），否则会探出方块正面（§3.6）。

> **单位约定（必读）**：**OBJ 用毫米**，`1000 = 1 米 = 1 格`。
> 建模软件里按米建、导出选毫米，一个 `1.0` 米高的柱子导出就是 `1000`。
> 摆放配置文件（`models/terminal/*.json`）用**格**：`1.0` = 一整格 = 1 米。
> 两者都由 `objUnitsPerBlock: 1000` 对齐，**不要**在 json 里改这个数去迁就错的 OBJ。详见 §3.1。
>
> ⚠️ **最常见的出错**：OBJ 顶点写成 `0.625` 这种米制小数，却仍声明 `objUnitsPerBlock: 1000`。
> 引擎会把 `0.625` 当成 `0.625 毫米`，整个端子缩到 0.0006 格——**模型"不显示"十有八九是这个原因**。

> 只要你守住这三条，端子放在墙、地面、天花板上都会自动朝外摆正，不用你管朝向。

## 一、你要交付什么

每个 OBJ 模型由**三个文件 + 若干贴图**组成，缺一不可：

| # | 文件 | 作用 | 谁维护 |
| --- | --- | --- | --- |
| 1 | `<名字>.obj` | 三角形几何 | **美术** |
| 2 | `<名字>.mtl` | 材质表：每个 `usemtl` 用哪张贴图 | 美术（引擎生成也行） |
| 3 | `<名字>.json`（包装） | 告诉加载器去哪找 1 和 2 | 引擎/程序 |
| 4 | `<名字>.png` 若干 | 贴图 | **美术** |

而**你要求的"每个模型都要有对应 json 配置"** 是**第 4 个文件之外的另一个 json**：

| # | 文件 | 作用 | 谁维护 |
| --- | --- | --- | --- |
| 5 | **摆放配置** `<条目名>.json` | 偏移 / 旋转 / 缩放 / 连接点校准 | **美术**（改完 F3+T 即见） |

> 目录上 3 和 5 是**两个不同的文件、放在两个不同的文件夹**，别搞混（见第二节）。
> 3 是「模型怎么被读进来」，5 是「模型摆在哪」。你现在纠结的"位置始终不对"，调的是 **5**。

## 三、坐标系约定（先读这一节，90% 的错位都来自这里）

### 3.1 单位

本项目**统一用毫米建模**：**1000 mm = 1 m = 1 格 = 1 个方块**。
配置里写的数字永远是**格/米**，和你在建模软件里量到的毫米只差一个 `/1000`。

| 哪里的数 | 单位 | 例子 |
| --- | --- | --- |
| **摆放配置 / 锚点**（`models/terminal/*.json`） | **1 = 1 整格 = 1 米 = 1000 mm** | 接线点离根部 500 mm → `"y": 0.5` |
| **OBJ 文件里的顶点**（`v` 行） | **毫米**（`objUnitsPerBlock: 1000`，默认值） | `z 625` = 625 mm = 0.625 格 |
| **`scale`** | 纯倍率 | `1.0` = 原样，`0.5` = 一半 |

- **配置里的数字只和毫米制有关**：量到 `500 mm` 就写 `0.5`。**不需要理会 OBJ 顶点用的什么单位。**
- **`scale` 是纯倍率**：`1.0`（默认）= 按 OBJ 画的大小，`0.5` = 一半，`2.0` = 两倍。
  它**不是单位换算**，所以写 `1.0` 不会让模型变小或变大。
- **`objUnitsPerBlock`** 只回答一个问题：这个 OBJ 的顶点里，**多少单位构成一整格**。
  - `1000` —— **默认值**，本项目统一的毫米标尺（`1000 mm = 1 格`）。**新建模型不用写，默认就是它**；
  - `16` —— 原版方块模型的标尺（方块跨度 `0..16`），仅用于极少数按旧标尺画的文件。

> 换句话说：**配置写 `"y": 0.5` 就是 500 mm，与 OBJ 顶点怎么写无关。**
> 渲染器按 `objUnitsPerBlock` 把顶点换算成格，这一步不需要你参与。
> 唯一的例外是老配置：旧版配置用的是 1/16 格，迁移时要把旧数值**除以 16**。
> `scale` 除外，它一直是倍率。

### 3.2 基准朝向 = north

所有模型都按 **`facing=north`** 摆放来建。在你的 OBJ 里，**+z 朝外（朝玩家）**，+x 朝玩家的**左**，+y 朝上。

方块模型（`models/block/*.json`）也是同一个约定：`north` 时背板贴着 **`z = 0..1`**
（薄薄一层，贴着 z 小的一侧）。
其余朝向由引擎把**整块**绕方块中心旋转（north → east/south/west 是绕 Y 轴 90°/180°/270°，
north → up/down 是绕 X 轴 ±90°，让网格面朝天 / 朝地）。

**端子座是六向表面件**：贴墙、平铺地面、倒挂天花板都能装。所以**你仍然只需要做 north 一份**。

引擎把 north 框架下的模型绕方块中心 (8,8,8) 做**正旋转**（行列式 +1，**不是镜像**）。
下表由真实 JOML 矩阵直接算出，不是手推的：

| 朝向 | 变换 | 生长轴 `+z` 去哪 |
| --- | --- | --- |
| north | 原样 | `+z` |
| south | `(x,y,z) → (16-x, y, 16-z)` | `−z` |
| east | `(x,y,z) → (z, y, 16-x)` ← 见下方注意 | `−x` |
| west | `(x,y,z) → (16-z, y, x)` ← 见下方注意 | `+x` |
| up（贴天花板） | `(x,y,z) → (x, 16-z, y)` | `−y` |
| down（铺地面） | `(x,y,z) → (x, z, 16-y)` | `+y` |

> ⚠️ 上面 east / west 两行**旧版写反过**（旧表里 east 的公式其实得到 `+x`）。
> 现在以代码里的 `FACES` 基向量表为准，逐项用 JOML 验证：六个朝向全部 `det = +1`，
> 且 `M·(0,0,1)` 与生长轴一致。**你不需要记这张表**——它只说明"做 north 一份就够"。

> ⚠️ 关键：**必须是正旋转**。用"翻转两个坐标"的写法得到的是镜像，模型会被翻得左右互换。
> 引擎用"屏幕右 / 屏幕上 / 生长方向"三根轴（`right × up = normal`）构造矩阵，保证不会镜像。

### 3.3 格子中心在哪（端子应放在哪里）

**引擎只把 OBJ 的 `(0,0,0)` 放到格子的中心，然后什么都不加。**

```text
cellCentre = blockCentre + right·(u − 0.5) + up·(v − 0.5)
```

- `right` = 沿脸面向右，`up` = 沿脸面向上，都由朝向决定；
- `u`、`v` 是格子在网格里的位置（均分）。

也就是说：**模型原点 = 格子中心 = 方块中心平面（`z = 0.5` 那一层）**。
`+z` 方向即朝房间生长。

> **引擎不再替你往房间方向推任何距离。** 早期版本会把每个端子沿生长方向
> 推出 `7/16` 格，好让脚底"踩在 1/16 厚背板的表面上"。这个假设只对一种背板成立，
> 而端子座可能是厚铸件、母线框、带自身厚度的支架，或者与方块面齐平的板——
> 自动偏移在这些情况下要么把端子压进硬件里，要么让它悬在空中。
> 而且它让美术每次摆顶点都要补偿一个看不见的 `7/16`。
>
> **现在：需要离墙多远，就画进模型里**（顶点直接写对应的毫米数），
> 或者写进摆放配置的 `offset`。两处都是看得见、改得动的地方。

所以 **OBJ 的 `(0,0,0)` 就是格子中心**。想让端子贴在墙上，就在模型里把 `z`
从墙体表面开始画——例如墙在某处、你想让底面贴住它，就按那个位置写顶点。

### 3.4 ★ 原点到底在哪：**模型底部**，不是模型中心

> **这是整份手册最重要的一条。OBJ 的原点 = 模型底部（脚底），不是模型中心。**

| 项 | 值 |
| --- | --- |
| **OBJ 原点 `(0,0,0)`** | **模型底部中心**（脚底中心） |
| `x = 0` | 模型**左右正中** |
| `y = 0` | 模型**前后正中**（在这个平面上对称） |
| `z = 0` | 模型**底部**，即贴住背板的那个面 |
| 生长方向 | **`+z`**（从背板朝房间伸出） |
| 模型高度 | 沿 `+z` 从 `0` 到 `长度`（**全部 `z ≥ 0`**） |

用大白话说：

- **模型整体待在 `z ≥ 0` 的半空间里**，`z < 0` 部分应该**没有东西**；
- 底面（脚）就是 `z = 0` 这一层；
- 想让它站着，就把它放在 `z = 0` 上往 `+z` 长。

**为什么原点在底部而不是中心**：

- 端子是"插在插座上"的东西，它的**接触点就是底面**；
- 原点在底面，意味着"这个模型从哪儿开始长"能被直接读到；
- 如果原点在模型中心，每次改模型高度都要重新调 `origin`，美术会被迫算数学。

**请务必不要**把模型建成 `z = −5 .. +5`（以中心为原点）。如果导出工具给你的原点在中心，
有两个办法：

1. **推荐**：在建模软件里把整个模型平移，让底面落在 `z = 0`，再导出；
2. 或者在摆放配置里写 `origin: {x:0, y:0, z:-高度/2}` 把 pivot 挪回底部（见 §4.2）。

> 判定方法：打开 `.obj`，所有 `v` 行的**第三个数字**（z）如果出现负数，或者最小值不等于 0，
> 就说明原点不在底部。LV 的占位文件全部满足 `z: 0 .. 10`，可以作为对照。

### 3.5 参考数值（当前占位模型）

| 项 | 值 |
| --- | --- |
| 底面 | `z = 0`，截面关于 `x = y = 0` 对称 |
| LV 截面 / 柱长 | `350 × 350` mm / `625` mm（`0.35 × 0.35` 格 / `0.625` 格） |
| MV / HV / EHV 截面 | `420` / `507.5` / `595` mm |
| 四级柱长 | 都是 `625` mm |

> 单看比例：四级柱长相同，只是粗细递增，所以越高等级看起来"越粗壮"。

### 3.6 ★ 尺寸由你决定，引擎不缩放

渲染器**不做任何自动缩放**。端子最终大小 = OBJ 里的数值 ÷ `objUnitsPerBlock` × 配置里的 `scale`，
而 `objUnitsPerBlock` 默认 `1000`（毫米制）、`scale` 默认 `1.0`（纯倍率），
所以**你画多大，它就有多大**。

需要你自己权衡的两件事：

| 约束 | 数值 | 说明 |
| --- | --- | --- |
| **一定不能超出格子**（横向） | 见下表 | 超了就会伸进隔壁格子甚至隔壁方块 |
| **深度**（沿 `+z`，朝房间） | 建议 ≤ `9/16` 格 = **`562.5` mm** | 原点在**格子中心**（方块中心平面）。从那里到方块**正面**（朝玩家那侧）还剩 `1/2` 格；再算上端子座自身占掉的厚度，建议净长不超过 `562.5` mm 即可稳稳留在方块内。超了就会探出方块正面 |
| 格子宽度 | LV `1/4` 格 = 250 mm、MV `1/2` = 500 mm、HV/EHV `1` = 1000 mm | 这是"格子的 100%"，建议留 10%~20% 空隙 |

**方向说明（容易搞反）**：端子从背板朝**房间**（玩家站着的那侧）生长，
所以深度超限的结果是**探出方块正面**、悬在过道里，**不是**扎进背后的墙。
背后的墙永远碰不到——背板本身就在墙上。

> ⚠️ **旧版占位模型（`z` 到 `10`、截面 `3.2`）已废弃并删除**：那些是 1/16 标尺的数字，
> 与现在的毫米约定不一致。新模型请直接按毫米建，柱长 `625`、截面按上表，
> 这样和 1/16 标尺下"柱长 10、截面 5.6"是同一尺寸。新模型可以画得更粗更好看，
> 只要横向不超格子、深度不超 `562.5` mm 就行。

**建议做法**：端子探出方块正面本身是允许的，但**别探太多**，否则视觉上会悬在过道里，
并且和贴墙放的其他方块打架。

### 3.7 ★ 碰撞盒来自你的模型，改模型就改碰撞

端子放上去之后**有碰撞体**：玩家会被它挡住、走不过去，瞄准射线也会打在它身上。
碰撞盒不是某个固定尺寸，而是**从你的文件里算出来的**：

| 部分 | 来源 | 说明 |
| --- | --- | --- |
| **端子本身** | OBJ 里**被面引用到的顶点**的包围盒 | 引擎的服务器端自己解析 `.obj`，取所有 `f` 行用到的 `v` 的 min/max，再按摆放配置（`offset`/`origin`/`rotation`/`scale`/`mirror`/`objUnitsPerBlock`）变换到格子里 |
| **端子座背板** | `blockstates` 指定的方块模型（`models/block/<级>_terminal_mount_<朝向>.json`）的 `elements` | 每一级厚度不同（LV `1/16`、MV `1.5/16`、HV `2/16`、EHV `2.5/16`），改了方块模型就跟着改 |

这意味着：

- **你是模型做多大，碰撞就多大**，不需要另外填任何数字。
- **没被任何面引用的顶点不参与计算**。导出时残留的多余顶点不会把碰撞盒撑大，
  所以改模型时不用特意去清理孤立点。
- 但**被引用的顶点一个都不会漏**：如果把长条、地线、吊环画在远处，碰撞盒会一直包到那里。
  这通常就是你想要的（"能框住模型的最小矩形"），但如果只是装饰性的细线，
  它也会变成一堵看不见的墙——**别把装饰画在离主体很远的地方**。
- **旋转会放大包围盒**。`rotation` 转了 45°，盒子会把旋转后的形状整个罩住，
  而不是跟着转（轴对齐包围盒的必然结果）。所以**尽量把模型画成轴对齐**，
  靠 `rotation` 只做小幅调整。
- **只包端子，不包线缆**。线缆是连接实体，没有碰撞。

> 端子拆掉后碰撞盒会立刻消失，背板留下；整座不装端子时只有背板那么薄，
> 不会变成一个实心方块。

### 3.8 明暗（法线）怎么来的

端子会被**逐面打光**：顶面最亮、南北面次之、东西面较暗、底面最暗（`1.0 / 0.8 / 0.6 / 0.5`），
和普通方块一致。这个明暗由**顶点法线**决定，所以：

- **`f` 行请带上法线索引**，格式 `f v/vt/vn`，例如 `f 1/1/1 2/2/1 3/3/1 4/4/1`。
- **只写 `f v/vt`（没有 `vn`）也能用**：加载器会用面法线自己算，但前提是顶点顺序正确
  （逆时针朝外）。顺序反了会变暗甚至发黑。
- **导出了 `vn` 但 `f` 行不引用它，等于没导**。Blender 里勾选的「写入法线」只有在
  面行带上第三段索引时才生效。
- **别用法线贴图/`map_Bump`**，引擎不读；明暗只认几何法线。

> 如果你发现某个端子「整片一个颜色、没有明暗」，先查 `f` 行有没有法线索引，
> 再用 `s 0`（平直着色）而不是 `s 1`（平滑着色）——`s 1` 会让整个模型共用一个朝向，
> 明暗就拉平了。

## 四、摆放配置格式（第 5 个文件）

```jsonc
{
  "offset":   { "x": 0.0, "y": 0.0, "z": 0.0 },   // 平移，单位：格（1 = 一整格 = 1 米）
  "rotation": { "x": 0.0, "y": 0.0, "z": 0.0 },   // 旋转，单位：度
  "scale": 1.0,                                    // 倍率，必须 > 0；1.0 = 按 OBJ 原样
  "origin":   { "x": 0.0, "y": 0.0, "z": 0.0 },   // 缩放/旋转中心，相对 OBJ 自身原点，单位：格
  "mirror": "",                                    // "" | "x" | "y" | "z"
  "mirrorOffset": 0.0                              // 镜像平面位置，单位：格
}
```

### 4.1 逐项含义

| 键 | 含义 | 正方向 | 单位 |
| --- | --- | --- | --- |
| `offset.x` | 左右平移 | 朝玩家**右** | 格 |
| `offset.y` | 上下平移 | **上** | 格 |
| `offset.z` | 前后平移 | **朝外（朝玩家）** | 格 |
| `rotation.x` | 绕 X 轴转（俯仰） | 右手定则：+x 指向玩家左侧，故正值=**顶部朝玩家倒** | 度 |
| `rotation.y` | 绕 Y 轴转（偏航） | 右手定则：从上往下看**逆时针** | 度 |
| `rotation.z` | 绕 Z 轴转（滚转） | 右手定则：+z 朝玩家，故正值=**顶部朝左倒** | 度 |
| `scale` | 等比缩放倍率，`1.0` = 原样 | — | 倍 |
| `origin.x/y/z` | 旋转 + 缩放的中心，**相对 OBJ 自身原点的偏移** | — | 格 |
| `mirror` | 沿某根轴镜像（见 4.2） | — | — |

**执行顺序**（从内到外）：`origin` 反平移 → `rotation` → `scale` → `mirror` → `offset` → 格子位置 → 朝向。

### 4.2 `origin` 和 `mirror` 到底怎么用

`origin` **不是**"模型在世界里的坐标"，而只是**"绕哪里转、以哪里为中心缩放"**，
数值是**相对 OBJ 自己 `(0,0,0)`** 的偏移，**单位是格**。

- **标准约定（原点在模型底部中心、朝 +z 长）：全填 0**，不用管。
  这时旋转和缩放都以"脚"为中心，符合直觉。
- **你的模型原点不在底部**（`v` 行出现负 z，例如模型建成了 `z = −5..+5`）：
  写 `origin: {x:0, y:0, z:-0.3125}`（即 `-5/16` 格），等于告诉引擎"把旋转中心挪到模型底部"。
  —— 这只是补救；**更推荐直接把模型平移到 `z ≥ 0` 再导出**（§3.4）。
- 想让柱子在底座上偏前/偏后长：改 `origin.z`，比改 `offset.z` 更"物理"，
  因为 `offset` 会连"插进背板多少"一起挪。

`mirror` 用于"**模型做反了**"的情况——例如轴朝着 -z 长。
`mirror: "z"` 会沿 z 轴镜像，`mirrorOffset` 是镜像平面的位置（相对 OBJ 原点，单位**格**）。
这里用的是**真镜像**（自动翻法线），所以不会出现内翻变黑。

> 注意：`mirror` 的存在会让行列式变成 −1；**这不是推荐做法**，优先在建模软件里把模型转正。

### 4.3 和尺寸的关系

**引擎不做任何自动缩放。** 端子最终大小 = OBJ 里的数值 ÷ `objUnitsPerBlock` × `scale`。

`objUnitsPerBlock` 默认 `1000`（毫米制），所以最常见的情况就是
`OBJ 数值 ÷ 1000` 格，即 **`625` 显示为 0.625 格 = 625 mm**，画多大显示多大。

- `scale: 1.0`（默认）= 保持你在 OBJ 里画的大小，**原样显示**；
- `scale: 0.5` = 整体缩小一半（绕 `origin`）；
- `scale: 2.0` = 整体放大一倍。

> 记住一句话：**`scale` 就是普通倍率，`1.0` 是"不变"**。
> 它**不**参与单位换算——单位换算由 `objUnitsPerBlock` 负责，所以配置里永远不会出现 `16`。

也就是说，"端子该多大"完全由你决定：要么改 OBJ，要么改这里。
**推荐改 OBJ**——这样模型和尺寸在同一个文件里，不容易对不上。

唯一的注意点仍是 §3.6 的**深度**：`+z` 净长超过 `562.5` mm（`9/16` 格）就会探出方块正面
（`scale` 也会同比放大深度，别只盯着横向）。

### 4.4 改完怎么看

游戏内按 **F3 + T** 重载资源包即可，**不用重启、不用重新编译**。

- 改 **摆放配置 `models/terminal/<样式id>.json`**：`F3+T` 立即生效，**不用重开存档**；
  重载时日志会打一行
  `Loaded 4 terminal pose file(s) from models/terminal; anchor(blocks): lv_terminal=(x, y, z) ...`，
  里面就是**实际生效的数值**——改完先看这一行，能立刻确认文件有没有被读到、读到的值对不对；
- 改 **`.obj` / `.mtl` / `.png`**：`F3+T` 会重新烘焙模型，**直接生效**；
- 配置写错时，控制台会打一行 `Model config ... is unusable (原因); falling back to the default pose for <样式>`，
  该样式退回默认姿态（可见、不会被误认为"改了没反应"），其它样式照常加载；
- 文件找不到时打 `No pose file for terminal style <样式> — expected <路径>`。
  **看到这一行说明配置完全没被应用**，先核对文件名：必须是
  `models/terminal/<样式id>.json`，例如 `lv_terminal.json`。
- 如果是 `.obj` 本身坏了，控制台会出现 `Unable to load model` / `Unable to bake model`，
  端子不显示——这时先看 json 里 `model` 路径是不是漏了 `models/`（见 §10）。

> **开发环境下 F3+T 读的是构建产物，不是 `src/main/resources`。**
> 游戏加载 `%TEMP%\stardustindustry-build\StardustIndustry-Core\resources\main\...`，
> 那是 `src/` 的一份**拷贝**；`F3+T` 只重读这份拷贝，**不会重新拷贝**。
> 所以改完源文件后必须：**关游戏** →
> `.\gradlew.bat :StardustIndustry-Core:processResources --rerun-tasks --no-configuration-cache`
> → 再启动。构建任务会自动同步资源，所以平时直接 `runClient` 不用手动跑这条；
> 只有**游戏已开着、又想应用源文件改动**时才需要它，而且**不能在游戏运行时跑**
> （Gradle 会与正在被读取的文件冲突，反而写回旧内容）。
> 换成正式 jar 后没有这个区别。

## 五、物品栏图标 ≠ 方块内样子

**端子**的物品图标**不是** OBJ，而是一张 **16×16 PNG**：

- `models/item/<tier>_terminal.json` 是 `item/generated`，只引用
  `textures/item/terminal_<tier>.png`；
- 所以**改 `.obj` 不会改变物品栏图标**，要改图标就换那张 PNG；
- 反过来说，图标与实机模型**互不影响**，美术可以分开处理。

> 为什么不用 OBJ 当图标：OBJ 走 GUI 特化变换链，最终大小取决于模型自身尺寸，
> 实测会撑到格子之外（"物品栏里特别大一个"）。用 PNG 更可控。

**端子座**的物品模型则**确实**复用方块模型（`models/item/<tier>_terminal_mount.json`
→ `parent: block/<tier>_terminal_mount_north`），它带着 `display` 段控制 GUI 里的摆放。
这种情况下：

- `display` 是**方块模型体系**的键，和 OBJ 无关；
- `transforms` 是 **OBJ 加载器**的键，两者不要混用。

⚠️ **两个常见坑**

1. 写 OBJ 的包装 json 时，`transforms` 必须直接写在顶层，**只包一层 `display`**。
   - ✅ `"transforms": { "gui": {...}, "ground": {...} }`
   - ❌ `"transforms": { "display": { "gui": {...} } }` ← **多包一层就完全不生效**
2. **`display` 关键字在 `neoforge:obj` 加载器下不生效**，务必用 `transforms`。

## 六、`.obj` 文件怎么建

### 6.1 硬性要求

| 要求 | 说明 |
| --- | --- |
| 单位 | **毫米，`1000` = 1 格 = 1 米**（导出时把一格按 1 米建、单位选毫米）。`objUnitsPerBlock: 1000` 是默认值；摆放配置另用"格"为单位（§3.1） |
| **原点** | **`(0, 0, 0)` = 模型底部中心**（脚底），必须；**不是模型中心**。模型沿 `+z` 生长，所有 `z ≥ 0`（见 §3.4） |
| 面 | 只接受 `f a/t b/t c/t` 的**三角形或四边形**；四边形会拆成两个三角形 |
| **面的顶点编号从 1 开始** | 这是 OBJ 规范：第一个顶点是 `1`，不是 `0`。写 `f 0/1 ...` 整块模型会不显示 |
| 绕序 | 从**外面看逆时针**（法线朝外） |
| 材质 | 每个面必须带 `usemtl`，名字要与 `.mtl` 里的 `newmtl` 一致 |
| 法线 | **不写 `vn`**。写了也不用，着色由游戏按面计算 |
| 反转面 | `automatic_culling: false` 时双面显示，但仍建议法线朝外，否则 `shade_quads` 下会偏暗 |
| 不要 | 不要用 `o`/`g` 分组做逻辑，引擎不区分 |

### 6.2 从 Blockbench 导出

> ⚠️ **Blockbench 的 pivot 和 OBJ 的原点是两回事。**
> 导出时 Blockbench 会按它自己的原点/缩放写 `v` 行，所以**导出后必须自己检查 `v` 行**，
> 不能想当然认为 pivot 对了顶点就对了。

1. 新建 **Generic Model**；网格大小选 `16×16×16`（与方块对齐）。
2. 建模时让模型的**底面**落在 `z = 0` 上、朝 `+z` 长。
3. 导出 **Wavefront (.obj)**，勾选 **Export .mtl**：
   - `Export groups in separate save folders`：**不勾**
   - `Export vertex colors`：不勾
   - `-Y is up`：**不勾**（游戏是 +Y 朝上）
4. **导出后检查**（这一步不能省，见下面的判定方法）：
   - 所有 `v` 行的第三个数（z）是否**全部 ≥ 0 且最小值 = 0**；
   - `x`、`y` 是否关于 `0` 对称（左右/前后居中）；
   - 如果不符合，**推荐回到建模软件里平移整个模型后重新导出**；
     —— 退路是在摆放配置里用 `origin` 补上差值（见 §4.2）。
5. 导出后**检查顶点编号**：`f` 行的第一个数字应当是 `1`。Blockbench 正常导出满足这条，
   但手写或用脚本生成时要特别留意（`f 0/1 ...` 会让模型整个消失）。
6. 把 `.obj` / `.mtl` 放到 `models/block/`，`.png` 放到 `textures/block/`。
7. 打开 `.mtl`，把 `map_Kd` 改成资源路径：`map_Kd stardustindustry:block/<名字>`（不要 `.png` 后缀）。

### 6.3 `.mtl` 格式

```mtl
newmtl body
Kd 1 1 1
map_Kd stardustindustry:block/terminal_lv_body

newmtl metal
Kd 1 1 1
map_Kd stardustindustry:block/terminal_lv_metal
```

- `map_Kd` 两行必须**只有一张**贴图，不要用 `map_Ks` / 法线贴图（引擎不读）。
- `Kd 1 1 1` 表示「贴图原色」，由染色逻辑另行处理，别改成其他颜色。

> ⚠️ **`map_Kd` 是必需的，不能只写 `Kd` 纯色。**
> Blender 默认导出只有 `Kd`（例如 `Kd 0.186911 0.186911 0.186911`），这样的 mtl
> 在游戏里**一定是紫黑棋盘**。原因是 NeoForge 的 OBJ 加载器
> （`ObjModel` → `resolveDirtyMaterial`）对没有 `map_Kd` 的材质**直接返回缺失贴图**，
> `Kd` 只作为颜色**乘在贴图上**，没有贴图可乘时它就是无效的。
>
> 所以「纯色材质」的正确做法是：**画一张纯色的 16×16 PNG**，再用 `map_Kd` 指向它。
> `Kd` 保持 `1 1 1` 即可。这是引擎的限制，不是配置错误。

> ⚠️ **材质名必须和 `.obj` 里的 `usemtl` 完全一致。** Blender 会照抄材质名
> （示例里是 `connectorLV`），大小写不同也算不一致。

### 6.4 包装 json（第 3 个文件）

```json
{
  "loader": "neoforge:obj",
  "model": "stardustindustry:models/block/terminal_lv.obj",
  "mtl_override": "stardustindustry:models/block/terminal_lv.mtl",
  "automatic_culling": false,
  "shade_quads": true,
  "flip_v": false,
  "emissive_ambient": false
}
```

| 键 | 建议值 | 含义 |
| --- | --- | --- |
| `automatic_culling` | `false` | 关掉自动剔除，薄片/单面不会消失 |
| `shade_quads` | `true` | 按法线做明暗，立体感靠它 |
| `flip_v` | `false` | 贴图 V 轴不翻转；在 Blockbench 里正着画的图就用这个 |
| `emissive_ambient` | `false` | 不做自发光 |

## 七、已实现：端子（`models/terminal/`）

**端子按"样式"独立，不按电压等级共用。** 每个端子物品有自己的样式 id
（`lv_terminal`、`mv_terminal`、……），对应三样东西：

| 样式 id | OBJ | 材质组 | 说明 |
| --- | --- | --- | --- |
| `lv_terminal` | `block/terminal_lv.obj` | `body` / `metal` | 4×4 网格，格子最窄 |
| `mv_terminal` | `block/terminal_mv.obj` | `body` / `metal` | 2×2 |
| `hv_terminal` | `block/terminal_hv.obj` | `body` / `metal` | 1×1，格子最大 |
| `ehv_terminal` | `block/terminal_ehv.obj` | `body` / `metal` | 1×1 |

以后同一个电压等级再加第二种端子（母线夹、瓷瓶、树脂绝缘子……），
只要在 `TerminalStyle` 里加一个常量、放一份新的 OBJ 和一份新的
`models/terminal/<样式id>.json`，**不用改渲染器，也不会覆盖已有端子的数值**。
两个样式也可以故意指向同一份摆放配置（`TerminalStyle` 的 `model` 参数），
那样它们外观相同但不冲突。

> 存档里记的是**样式 id**（NBT 键 `Style`）。旧存档的 `Tier=lv` 会自动映射到
> `lv_terminal`，读进来照常显示，下次保存就写新格式。

> **引擎不缩放**（§3.6 / §4.3），上表"格子最窄/最大"只是提醒你这四级的**美术尺寸应有差别**，
> 程序不会替你调整。

**当前占位几何**：最简单的长方体（`metal` 脚板 / 帽 + `body` 柱身），
**只是用来验证管线的占位件，请整体替换**。

> **`lv_terminal` 的 OBJ / MTL 暂时缺失**（已删除，等待美术按本手册重做）。
> 缺失期间引擎会在日志打一行
> `Terminal model stardustindustry:block/terminal_lv did not bake`，LV 端子不显示，
> 但游戏照常运行、其它样式不受影响。
> 交付时只需放回 `models/block/terminal_lv.obj` 和 `.mtl`；
> 包装文件 `models/block/terminal_lv.json` 和摆放配置 `models/terminal/lv_terminal.json` 都还在，不用重建。

### 7.1 端子摆放配置（每个样式一份 `models/terminal/<样式id>.json`）

> **单位：1 = 1 整格 = 1 米 = 1000 mm**，和建模软件（毫米制）一致（§3.1）。
> `offset / origin / anchor / mirrorOffset` 都是**格/米**；`scale` 是**纯倍率**，`1.0` = 按 OBJ 原样。
> `objUnitsPerBlock` 是**唯一**与 OBJ 顶点单位有关的一项，只声明文件用的是什么单位，不影响上面这些数字。

四个文件当前内容相同：

```json
{
  "offset":   { "x": 0.0, "y": 0.0, "z": 0.0 },
  "rotation": { "x": 0.0, "y": 0.0, "z": 0.0 },
  "scale": 1.0,
  "origin":   { "x": 0.0, "y": 0.0, "z": 0.0 },
  "mirror": "",
  "mirrorOffset": 0.0,
  "anchor":   { "x": 0.0, "y": 0.0, "z": 0.0 },
  "objUnitsPerBlock": 1000.0
}
```

- **`scale` = `1.0`** 是"正常大小"。写 `0.5` 就是画的一半大，写 `2.0` 是两倍。
  它只是倍率，**不承担单位换算**。
- `origin` 全为 0，是因为 **OBJ 的原点已经在底部中心**（§3.4）——
  这是"模型按约定建"时应该有的正常状态。**如果你的模型原点不在底部，才需要改这里。**
- **`anchor` 全是 0 = 模型原点**（模型底部中心，贴在背板朝房间的那一面，见下文）。
  想让线从端子尖端出来，就填正的 `z`（记住 500 mm = 0.5）。
- **`objUnitsPerBlock`**：OBJ 顶点每格多少个单位。`16` = 原版方块模型标尺（方块跨度 `0..16`），
  `1000` = 文件直接按毫米导出。**只有导出单位变了才需要改它**，改配置数字和改它无关。

**从旧版（1/16 单位）换算过来**：`offset / origin / anchor / mirrorOffset` 把旧数值**除以 16**
（旧 `"offset": {"z": 4}` → 新 `"z": 0.25`）；`scale` 不用变，它一直是倍率。
（新项目一律按毫米建模：`500 mm → 0.5`，与旧版的 `/16` 是两套来源，别混用。）
**注意**：`anchor` 的原点先后经历过"格子中心再退板面""方块中心"，现在是**模型原点**，
所以旧存档的锚点位置会变化一次——这次是最终修正，之后就以模型原点为准。

#### `offset` 的含义（这一项以前"改了没反应"，已修正）

`offset` 是**贴着脸的方向**，在朝向旋转**之后**应用，所以六个朝向含义一致：

| 轴 | 含义 | 单位 |
| --- | --- | --- |
| `x` | 沿脸面向**右**（玩家面对背板时） | 格 |
| `y` | 沿脸面向**上** | 格 |
| `z` | **出板、朝房间**（正 = 离开墙，负 = 陷进板里） | 格 |

举例：`"z": 0.5` = 端子整体往外挪半格；`"y": 0.0625` = 往上挪 1 像素（1/16 格）。

以前 `offset` 在模型自己的 north 坐标系里、旋转**之前**应用，结果：
贴在**东西墙**上时 `z` 会把端子横着推，贴在**地面/天花板**上时 `z` 会把端子上下推。
这就是"改 `lv.json` 完全没效果"的真正原因。

#### `anchor` 的含义（线缆从哪里出来，和模型完全分开）

`anchor` 是**线缆端点**的位置，与 `offset` / `rotation` / `scale` / `origin` **没有任何关系**：

- **单位是"格/米"**：`1.0` = 一整格 = 1 米 = 1000 mm。项目统一用**毫米**建模，
  所以你在建模软件里量到多少毫米，就**除以 1000** 填进来；
- **坐标原点是「模型原点」**——也就是建模软件里 OBJ 自己的 `(0,0,0)`：
  柱子底部中心、贴在背板朝房间的那一面。`(0, 0, 0)` 就是这一点；
- 轴的含义和 `offset` 一样：`x` 右、`y` 上、`z` 出板。

**怎么取值**：

```
毫米 ÷ 1000 = 米 = 格      →  直接填
```

例：端子的接线点离底座 **500 mm**，就写 `y: 0.5`。

**常用参考点**（以贴在北墙的 HV/EHV 1×1 端子为例，原点为模型根部中心）：

| 想要的位置 | 建模软件里（毫米） | 写进配置 |
| --- | --- | --- |
| 模型原点（根部，贴背板） | `(0, 0, 0)` mm | `(0, 0, 0)` |
| 接线点离根部 500 mm | `(0, 500, 0)` mm | `y: 0.5` |
| 占位柱尖端（原占位 OBJ 的 `z = 10` 旧单位） | — | `z: 0.625` |
| 往右 1 像素 | `(62.5, 0, 0)` mm | `x: 0.0625` |

> **历史坑**：锚点原点先后试过"格子中心再退板面"和"方块中心"。
> 前者让 `(0,0,0)` 落在方块角上；后者虽然 `0` 确实是方块中心，但**建模软件里不显示这个点**，
> 它离模型根部还差一个背板厚度（而且 LV 背板 1/16、HV 背板 2/16，各等级还不一样），
> 美术只能靠试。现在原点就是模型原点，量到多少填多少。

> **关于 OBJ 顶点单位**：配置里的数字与 OBJ 顶点用什么单位**无关**。
> 本项目模型一律**以毫米建模**（默认 `objUnitsPerBlock: 1000`），渲染器据此把顶点换算成格。
> **你不需要为配置做任何换算**——毫米直接除以 1000 写进配置，顶点照常按毫米导出即可。

**多格端子（LV 4×4 / MV 2×2）**：每个格子有**自己**的模型原点（就是那一格里端子的根部），
所以 `anchor` 对每一格的含义完全一样，不需要任何额外补偿。

为什么必须分开（用户明确要求）：端子是会反复重导出的美术件，而线缆要接的那一点
是硬的电气位置。绑在一起的话，每次调模型都会把线一起拽走，反过来调线也会拽模型。

**调试口诀**：

| 现象 | 先改 |
| --- | --- |
| 端子整体离开/陷进背板 | `offset.z`（正 = 朝房间/朝外，单位格） |
| 端子偏到格子左上/右下 | `offset.x` / `offset.y` |
| 端子躺着 / 朝天 | `rotation.x`（±90） |
| 端子朝向反了（朝墙里） | `rotation.y` = 180 |
| 端子太大/太小 | **先改 OBJ**；实在不想动模型再改 `scale`（`1.0` = 原样，`0.5` = 一半） |
| 端子绕着自己转歪了 | `origin`（把旋转中心挪到模型底部） |
| 端子整根顶出方块正面 | 净长超了 `9/16` 格（§3.6），缩短 OBJ 的 `+z` 长度 |
| **线缆没接在端子上 / 悬空/穿模** | 改 `anchor`，**不要**改 `offset` |
| **模型调好了线却跟着跑** | 说明误改了 `anchor`；把它改回上一版 |
| 改了 json 没反应 | `F3 + T`；先看日志有没有 `No pose file for terminal style ...`（文件名不对）和 `Model config ... is unusable`（内容不对），再看 `anchor(blocks):` 那行的数值。**开发环境下**还要确认 Gradle 已同步源文件（见 §4.4 末尾的注意事项） |

## 八、已规划：线缆（`models/cable/`）

> **本轮尚未实现**，框架建好后启用同一套配置格式，并额外增加 `fit` 段。

电缆是"一格连出、跨格拉伸"的模型，所以除了 4.1 的四项，还要声明**连接点**：

```jsonc
{
  "fit": ["lv"],                    // 这套模型适配哪些等级；空数组 = 全部
  "offset":   { "x": 0, "y": 0, "z": 0 },      // 单位：格
  "rotation": { "x": 0, "y": 0, "z": 0 },
  "scale": 1.0,                                // 倍率，1.0 = 按 OBJ 原样
  "origin":   { "x": 0, "y": 0, "z": 0 },      // 旋转/缩放中心（格）；按"原点在底部"的约定就是 0
  "anchor":   { "x": 0, "y": 0, "z": 0 },      // 线缆连接点（格），以模型底部为原点
  "stretch":  { "x": 1.0, "y": 1.0, "z": 1.0 }  // 允许被拉长的轴与比例
}
```

| 键 | 含义 |
| --- | --- |
| `fit` | 适配等级。`["lv"]` 表示只给 LV 用；一套通用模型写 `["lv","mv","hv","ehv"]` |
| `offset` / `origin` / `anchor` | 长度，**单位是格**（1 = 一整格） |
| `scale` | 等比缩放倍率，默认 `1.0`（= 按 OBJ 原样大小） |
| `stretch` | 逐轴拉伸上限；`1.0` = 不拉伸，`>1` = 允许拉到此倍数，负值 = 禁用该轴 |

> 为什么 `anchor` 单独一项而不是直接改 `origin`：
> `origin` 是旋转中心，`anchor` 是**电气上贴合的那一点**。
> 一个电缆接头可能用 `origin` 在底座中心，但 `anchor` 在接头末端，两者必须分开。

**等级尺寸建议**（未定稿，等实机）：

| 等级 | 导体直径 | 绝缘外径 | 最小弯折半径 |
| --- | --- | --- | --- |
| LV (380 V) | 1.0 | 2.0 | 2.0 |
| MV (10 kV) | 1.5 | 3.5 | 5.0 |
| HV (110 kV) | 2.0 | 5.0 | 8.0 |
| EHV (500 kV) | 2.5 | 7.0 | 12.0 |

## 十、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 物品栏里模型巨大 | `transforms` 多包了一层 `display` | 见 §5 |
| 游戏里看不到，日志报 `Unable to load model` | 包装 json 的 `model` 路径不对（要写 `models/block/x.obj`，**带 `models/`**） | 修路径 |
| 黑紫格子 | **mtl 只有 `Kd` 没有 `map_Kd`**（Blender 默认导出就是这样）；或 `map_Kd` 路径错 / 贴图没放对目录 | 画一张纯色 PNG 并用 `map_Kd stardustindustry:block/...` 指向它（**不带 `.png`**），放 `textures/block/`。见 §6.3 |
| 模型朝向在 north 正确、其他朝向错位 | 配置里的偏移写成了世界坐标 | `offset` 是**沿脸面**的（右/上/出板），六个朝向含义一致；`anchor` 同理 |
| 模型内侧全黑 | 法线朝内 | 在 Blockbench 里翻转面 |
| **模型完全不显示** | `f` 行里出现了顶点编号 `0`（OBJ 编号从 1 开始） | 重新导出，或把编号整体 +1 |
| 模型一半黑一半亮 | 面的绕序内外不一致 | 在 Blockbench 里统一翻转朝内的面 |
| 改了 json 没反应 | 没重载，或文件名/路径不对 | `F3 + T`；文件名必须是 `models/terminal/<样式id>.json`；看日志有没有 `No pose file` |
| **端子整体嵌进墙里一半** | OBJ 的原点在**模型中心**而不是底部（`v` 行有负 z） | 见 §3.4，把模型平移到 `z ≥ 0` |
| **端子整根探出方块正面、悬在过道里** | OBJ 的净长超过 `9` 单位 | 缩短柱长（§3.6） |
| **四个等级大小完全一样** | 这是正常的：引擎不缩放，四级都用同一尺寸的 OBJ | 想分级就把 OBJ 改成不同尺寸 |
| 端子座转一下模型还在原位 | 这是 bug，不是配置问题 | 报告给程序 |
| 平铺地面 / 倒挂天花板上格子错位 | 格子基向量没随朝向换（贴墙时"上"= 世界 Y，平铺时"上"= 世界 Z） | 报告给程序 |
| 地面上点不到格子 / 提示"点在网格外了" | 地面、天花板的 `cellFromHit` 少了 up/down 两个分支（旧版本 bug） | 已修；若复现请报告 |
| 朝东和朝西的模型对调 | 用的是镜像而不是旋转（行列式 −1） | 见 §3.2 的警告 |

## 十一、验收清单（交付前自查）

**几何**

- [ ] `.obj`、`.mtl`、包装 `.json`、摆放 `.json`、所有 `.png` 齐全
- [ ] **OBJ 原点是模型底部中心**：所有 `v` 行 `z ≥ 0` 且最小值 = `0`（§3.4）
- [ ] `x`、`y` 关于 `0` 对称（模型左右/前后居中）
- [ ] 模型沿 **`+z`** 生长（不是 `+y`、不是 `-z`）
- [ ] 横向尺寸**不超出格子**（LV `1/4` 方块、MV `1/2`、HV/EHV `1`）
- [ ] 净长（`+z` 的最大值）≤ `9` 单位，否则会探出方块正面
- [ ] `f` 行的顶点编号**从 1 开始**（出现 `0` 会导致模型不显示）

**材质与配置**

- [ ] `.mtl` 每个 `newmtl` 都有 `map_Kd stardustindustry:block/...`（不带 `.png`）
- [ ] 摆放 json 用 `origin: {0,0,0}`（原点在底部时）或正确的底部偏移
- [ ] 摆放 json 能被任何 JSON 校验器解析（无多余逗号）

**游戏内**

- [ ] `F3 + T` 后，在**六个朝向**都检查一遍（north / east / south / west / 贴地 / 顶棚）
- [ ] 物品栏图标单独看一眼（§5，是独立 PNG）
